Transformers & Attention

5 concepts
The architecture behind GPT, Claude, etc.
  1. ☆
    Self-attention mechanism
    Mechanism: Computes dynamic token alignment via Scaled Dot-Product Attention: Attention(Q,K,V) = softmax(QK^T / √d_k)V. Scaling by √d_k prevents the dot products from growing excessively large for high dimensions, which would push softmax into regions with vanishingly small gradients. Complexity: O(N²) time and memory complexity with sequence length N.
    🎬YT🌐G
  2. ☆
    Multi-head attention
    Architecture: Linearly projects queries, keys, and values into h distinct subspace representations: MultiHead(Q,K,V) = Concat(head_1, ..., head_h)W^O. Trade-off: Multi-Head Attention (MHA) allocates separate K/V heads per Q head; Multi-Query Attention (MQA) shares 1 K/V head across all Q heads (drastic KV-cache memory reduction); Grouped-Query Attention (GQA, e.g. LLaMA 3) groups Q heads into G subsets per K/V head, striking the optimal balance between inference throughput and modeling expressivity.
    🎬YT🌐G
  3. ☆
    Positional encoding (sinusoidal, RoPE)
    Mechanics: Inject sequence position into permutation-invariant self-attention. Absolute Sinusoidal: Adds fixed trigonometric frequencies PE(pos, 2i) = sin(pos/10000^(2i/d)). Rotary Position Embedding (RoPE): Multiplies Q and K representations by an orthogonal rotation matrix in 2D complex conjugate planes, ensuring dot-product depends purely on relative distance m - n. Enables length extrapolation via NTK-aware scaling and YaRN.
    🎬YT🌐G
  4. ☆
    Encoder vs decoder vs encoder-decoder
    Taxonomy: Encoder-only (BERT): Full bidirectional attention over all tokens; optimal for classification and dense embeddings. Decoder-only (GPT, LLaMA): Causal autoregressive triangular masking preventing future token visibility; standard for text generation. Encoder-Decoder (T5, BART): Bidirectional encoder with cross-attention decoder; specialized for translation and summarization.
    🎬YT🌐G
  5. ☆
    Layer normalization & residual connections
    Stability: Residuals: Skip connections x + SubLayer(x) provide identity gradient paths, mitigating vanishing gradients in deep networks. LayerNorm: Pre-LN (normalizing before attention/FFN) provides stable gradient flow without warmup schedules, replacing legacy Post-LN. Modern LLMs favor RMSNorm (Root Mean Square Normalization), dropping mean-centering for 10-15% compute speedup.
    🎬YT🌐G

Tokens & Tokenization

4 concepts
Text → numbers. The interface.
  1. ☆
    Byte-Pair Encoding (BPE)
    Algorithm: Subword tokenization starting with raw bytes and iteratively merging the most frequent adjacent character/token pairs into a fixed vocabulary (e.g. 32k to 128k tokens). Balances vocabulary size against sequence length, eliminating out-of-vocabulary (OOV) tokens while compressing text to ~4 chars/token in English.
    🎬YT🌐G
  2. ☆
    Tokenizer behavior (whitespace, unicode)
    Gotchas: Leading whitespace (' apple' vs 'apple') produces completely different token IDs and embeddings; non-Latin Unicode scripts (Devanagari, Cyrillic, Chinese) suffer token bloat (3-8x more tokens per word than English), directly multiplying inference latency and API costs. Always inspect tokenizer output for whitespace and casing artifacts.
    🎬YT🌐G
  3. ☆
    Context window limits
    Memory Dynamics: KV-cache memory scales linearly with context length: Bytes = 2 * 2 * n_layers * n_kv_heads * d_head * seq_len * batch_size. At 128k context, a single batch KV cache consumes tens of gigabytes of VRAM. Requires vLLM PagedAttention (virtual paging eliminating fragmentation) and attention kernel optimizations (FlashAttention-2/3) to execute efficiently.
    🎬YT🌐G
  4. ☆
    Token cost optimization
    Optimization: Minimize token consumption via prompt compression (LLMLingua pruning low-perplexity tokens), prefix caching (reusing KV states across calls sharing identical system prompts), and schema minimization (abbreviated keys in JSON or using compact TOML/YAML schemas).
    🎬YT🌐G

Training & Inference

6 concepts
How models learn and respond.
  1. ☆
    Pretraining (next-token prediction)
    Pretraining: Unsupervised self-supervised learning predicting next token over trillions of tokens using Cross-Entropy loss. Governed by Chinchilla Scaling Laws: compute-optimal training requires scaling tokens and parameters equally (ratio ~20:1 tokens per parameter).
    🎬YT🌐G
  2. ☆
    Supervised fine-tuning (SFT)
    Supervised Fine-Tuning: Teaches conversational format and task execution using curated high-quality (prompt, response) pairs. Masked cross-entropy loss applied exclusively to target response tokens, preserving the base model's general knowledge while aligning output behavior.
    🎬YT🌐G
  3. ☆
    RLHF (Reinforcement Learning from Human Feedback)
    RLHF: Trains an explicit scalar Reward Model on pairwise human preference comparisons (Bradley-Terry model). Updates the LLM policy using Proximal Policy Optimization (PPO) with a per-token KL-divergence penalty against the reference model to prevent reward hacking and model collapse.
    🎬YT🌐G
  4. ☆
    DPO (Direct Preference Optimization)
    DPO Mechanics: Mathematically derives the optimal policy loss directly from the Bradley-Terry preference objective: L_DPO = -E[log σ(β log(π_θ(y_w|x)/π_ref(y_w|x)) - β log(π_θ(y_l|x)/π_ref(y_l|x)))]. Completely bypasses training a separate reward model and eliminates unstable PPO reinforcement learning loops.
    🎬YT🌐G
  5. ☆
    Inference: temperature, top-p, top-k
    Inference Sampling: Temperature: Scales logits z_i / T before softmax; T → 0 yields deterministic greedy argmax, while higher T flattens distribution. Top-p (Nucleus): Restricts sampling to the smallest cumulative probability mass ≥ p (typically 0.8-0.95). Top-k: Hard cutoff to top k candidate tokens. Combine low T with Top-p for reliable factual extraction.
    🎬YT🌐G
  6. ☆
    Sampling strategies
    Search Strategies: Greedy Search: Picks argmax token at each step (fast, prone to repetitive loops). Beam Search: Maintains B most probable candidate sequences (standard in translation, detrimental for open-ended creative generation). Speculative Sampling: Small draft model generates K speculative tokens; target model validates all K in a single forward pass, achieving 2-3x speedup.
    🎬YT🌐G

2.1

Core Techniques

6 concepts
What every prompt engineer knows.
  1. ☆
    Zero-shot prompting
    Technique: Providing task instructions directly in natural language without input-output exemplars. Effective with modern frontier models for standard reasoning, classification, and summarization tasks where explicit zero-shot transfer suffices.
    🎬YT🌐G
  2. ☆
    Few-shot prompting
    In-Context Learning: Providing 2-5 representative (input, output) demonstrations. Drastically improves structural adherence, domain-specific formatting, and edge-case handling. Dynamic few-shot uses vector similarity search to pull the most semantically relevant exemplars for each incoming query.
    🎬YT🌐G
  3. ☆
    Chain-of-Thought (CoT)
    Reasoning Chains: Elicits multi-step intermediate reasoning before emitting the final answer ('Think step-by-step'). Allocates additional computational budget (tokens) to reasoning, overcoming feed-forward depth limitations on complex arithmetic, logic, and multi-hop planning.
    🎬YT🌐G
  4. ☆
    Self-consistency
    Ensemble Reasoning: Samples N independent reasoning paths from the model at temperature > 0.5 using Chain-of-Thought, then aggregates the final answers via majority voting. Substantially improves accuracy on mathematical and symbolic reasoning tasks by filtering random reasoning errors.
    🎬YT🌐G
  5. ☆
    Tree of Thoughts (ToT)
    Tree of Thoughts: Generalizes CoT by exploring reasoning as an explicit tree where nodes represent intermediate thoughts. Uses heuristic evaluation prompts or lookahead search (BFS/DFS) to explore, backtrack, and evaluate multiple candidate reasoning trajectories.
    🎬YT🌐G
  6. ☆
    System prompts vs user prompts
    Prompt Hierarchy: System Prompt: Out-of-band persistent developer instructions defining persona, behavioral boundaries, response schemas, and guardrails; privileged over user input. User Prompt: Dynamic task request containing untrusted user inputs. Always isolate user input using XML delimiters to prevent prompt injection.
    🎬YT🌐G
2.2

Structured Output

4 concepts
Getting parseable responses.
  1. ☆
    JSON mode / response_format
    Constrained Decoding: Enforces strict JSON grammar at the token generation layer by masking non-compliant vocabulary logits at each decoding step. Guarantees 100% syntactically valid JSON matching target schemas without post-processing failures.
    🎬YT🌐G
  2. ☆
    Function/tool calling
    Function/Tool Calling: Model outputs structured JSON specifying tool name and arguments conforming to an OpenAPI/JSON-Schema specification. Execution happens on the client/application side; returned results are appended as tool-role messages for final synthesis.
    🎬YT🌐G
  3. ☆
    XML tags for structure (Anthropic)
    XML Delimiters: Claude and Anthropic models are trained to parse and generate hierarchical XML tags (e.g. <context>, <scratchpad>, <response>). Drastically reduces cross-talk between instructions, retrieved context, and user inputs.
    🎬YT🌐G
  4. ☆
    Pydantic / Instructor for typed outputs
    Validation Frameworks: Libraries (Instructor, Pydantic) that wrap LLM structured outputs with schema validation, type coercion, and automated self-correction loops (feeding validation exception tracebacks back into the model for iterative repair).
    🎬YT🌐G
2.3

Advanced Patterns

2 concepts
Beyond basic prompting.
  1. ☆
    Prompt chaining (decomposition)
    Decomposition: Deconstructs a monolithic complex prompt into a sequential Directed Acyclic Graph (DAG) of isolated single-responsibility prompts. Prevents context degradation and enables unit testing and caching of intermediate prompt stages.
    🎬YT🌐G
  2. ☆
    Self-critique / refinement loop
    Refinement: Two-pass generation pattern: Generator model produces initial output; Critic model (or generator with rubrics) evaluates against constraints (correctness, style, safety); Refiner model patches identified defects. Boosts code generation and drafting accuracy.
    🎬YT🌐G

3.1

RAG Pipeline Stages

7 concepts
End-to-end flow.
  1. ☆
    Document loading & parsing
    Ingestion: Document conversion from heterogeneous formats (PDFs, DOCX, HTML, audio transcripts) into clean structured text. Layout-aware parsers (unstructured, OCR, vision LLMs) preserve tables, headers, and document hierarchy vital for semantic coherence.
    🎬YT🌐G
  2. ☆
    Chunking strategies
    Chunking: Fixed-size: Sliding window with token overlap (e.g. 512 tokens with 50-token overlap). Recursive: Splits by natural structural boundaries (paragraphs → sentences → words). Semantic: Computes moving embedding distance between consecutive sentences, splitting where distance spikes exceed a threshold. Parent-Child: Indexes small child chunks for vector search, retrieves larger parent chunk for generation.
    🎬YT🌐G
  3. ☆
    Embeddings (sentence-transformers, OpenAI ada)
    Dense Representations: Bi-encoder models (e.g. text-embedding-3, BGE, E5) map text chunks to d-dimensional vectors (e.g. 768 or 1536 dims). Semantic similarity measured via Cosine Similarity (u · v) / (||u|| ||v||) or Dot Product on normalized embeddings.
    🎬YT🌐G
  4. ☆
    Vector storage & ANN search
    ANN Indexing: Approximate Nearest Neighbor algorithms: HNSW: Multi-layer navigable graph (skip-list on graphs); fast sub-10ms search with high recall, memory-heavy. IVF (Inverted File): Clusters space into Voronoi cells; searches only centroids nearest to query. PQ (Product Quantization): Compresses vectors into compact byte codes for 4-16x RAM savings.
    🎬YT🌐G
  5. ☆
    Retrieval (dense, sparse, hybrid)
    Hybrid Retrieval: Combines dense semantic retrieval (captures conceptual meaning, misses rare keywords/IDs) with sparse lexical retrieval (BM25, inverted index matching exact keywords). Merged using Reciprocal Rank Fusion: RRF_score(d) = Σ 1 / (60 + rank_i(d)).
    🎬YT🌐G
  6. ☆
    Reranking (Cohere, cross-encoder)
    Cross-Encoder Reranking: Re-scores top-k candidates (e.g. top 50) using a cross-encoder model (Cohere Rerank, BGE-Reranker) that performs full all-to-all attention across query and document jointly. Drastically improves precision over bi-encoder cosine ranking at modest latency cost (~20-50ms).
    🎬YT🌐G
  7. ☆
    Prompt construction with retrieved context
    Prompt Synthesis: Formats retrieved chunks into the prompt context with source attribution markers, temporal metadata, and explicit grounding instructions ('Answer ONLY using retrieved context; if insufficient, state unknown') to prevent hallucinations.
    🎬YT🌐G

Vector Databases

6 concepts
Storage + ANN search.
  1. ☆
    Pinecone
    Managed SaaS: Serverless, fully managed vector database with decoupled compute/storage and native metadata filtering. Optimized for turnkey cloud operations with zero index tuning overhead.
    🎬YT🌐G
  2. ☆
    Weaviate (open source)
    Multi-Modal DB: Open-source vector engine supporting graph-like cross-references, hybrid vector-BM25 search, and pluggable vectorizer modules. Written in Go, supports horizontal clustering.
    🎬YT🌐G
  3. ☆
    Qdrant (Rust)
    High-Performance Engine: Open-source vector database written in Rust. Features payload-based pre-filtering, quantized vector storage in RAM/mmap, and rapid HNSW index updates with sub-millisecond p99 latencies.
    🎬YT🌐G
  4. ☆
    Chroma (lightweight)
    Embedded Store: Lightweight, in-process or local client-server vector store. Excellent for local prototyping, unit tests, and single-host applications without distributed infrastructure.
    🎬YT🌐G
  5. ☆
    Postgres + pgvector
    Relational Extension: Open-source vector extension for PostgreSQL. Adds vector data type with HNSW and IVFFlat indexing. Ideal for existing Postgres stacks serving up to 10-20M vectors; enables transactional ACID joins between relational data and vector embeddings.
    🎬YT🌐G
  6. ☆
    FAISS (in-process)
    In-Memory C++ Library: Facebook AI's low-level library for dense vector similarity search and clustering. Provides GPU-accelerated index construction, PQ compression, and highly optimized CPU SIMD vector operations.
    🎬YT🌐G
3.3

Advanced RAG

6 concepts
Beyond naive RAG.
  1. ☆
    Query rewriting / decomposition
    Query Transformation: Uses an LLM to rewrite ambiguous or conversational user queries into standalone, search-optimized search terms, or decomposes complex multi-intent questions into parallel sub-queries.
    🎬YT🌐G
  2. ☆
    HyDE (Hypothetical Document Embeddings)
    HyDE: Hypothetical Document Embeddings: Prompts an LLM to generate a hypothetical answer to the query, then embeds the generated answer. Shifts query vector from the question manifold into the document manifold, boosting zero-shot recall.
    🎬YT🌐G
  3. ☆
    Contextual retrieval (Anthropic)
    Contextual Retrieval: Anthropic technique: Prepends a concise document-level context blurb to each individual chunk prior to embedding and indexing. Resolves pronoun ambiguity and isolated domain references, improving retrieval recall by up to 35-49%.
    🎬YT🌐G
  4. ☆
    Multi-hop RAG
    Multi-Hop Retrieval: Iterative retrieve-read-reason loop for complex questions requiring information across disparate documents. Intermediate retrieved facts generate follow-up search queries until the answer can be fully synthesized.
    🎬YT🌐G
  5. ☆
    RAG evaluation (Ragas, TruLens)
    RAG Triad Metrics: Evaluates RAG quality across 3 orthogonal dimensions: Context Relevance: Are retrieved chunks focused on the query? Groundedness / Faithfulness: Is the answer mathematically derived from the context? Answer Relevance: Does the answer directly address the user's prompt?
    🎬YT🌐G
  6. ☆
    Long-context vs RAG tradeoff
    Context vs RAG: Long-context LLMs (1M+ tokens) allow dumping entire document corpora directly into context, but suffer from high latency, linear cost scaling, and 'Lost in the Middle' attention degradation. Hybrid RAG (filtering 10k relevant tokens via vector search) remains 10x faster and cheaper.
    🎬YT🌐G

4.1

Agent Patterns

7 concepts
Designs that actually work in production.
  1. ☆
    Tool-augmented LLM (function calling loop)
    Basic Tool Loop: Simplest agent loop: System prompt defines tools → model emits tool call → runtime executes tool → tool output appended → model generates final response or triggers next tool call until termination.
    🎬YT🌐G
  2. ☆
    ReAct (Reason + Act)
    ReAct Pattern: Interleaves Reasoning ('Thought') and Action ('Act' + 'Observation') steps. Explicit thoughts allow the agent to decompose tasks, track goal progress, handle exceptions, and formulate informed tool queries.
    🎬YT🌐G
  3. ☆
    Plan-and-Execute
    Plan-and-Solve: Decouples planning from execution: Planner model generates a structured list of subtasks; Executor agent iterates through subtasks sequentially, updating state. Reduces wandering and token costs on long-horizon workflows.
    🎬YT🌐G
  4. ☆
    Router pattern
    Intent Routing: Lightweight classifier (small model, embeddings, or regex) categorizes incoming user input and routes to specialized downstream prompts, agents, or RAG collections, minimizing latency and cost.
    🎬YT🌐G
  5. ☆
    Parallelization (fan-out)
    Fan-Out Execution: Orchestrator decomposes independent subtasks (e.g. searching 5 distinct sources), executes tool invocations in parallel async workers, and joins results in an aggregator prompt for final synthesis.
    🎬YT🌐G
  6. ☆
    Orchestrator-Workers
    Hierarchical Multi-Agent: Supervisor agent delegates sub-problems to specialized worker agents (e.g. ResearchAgent, CodingAgent, ReviewAgent). Each worker maintains its own isolated context, preventing context contamination.
    🎬YT🌐G
  7. ☆
    Evaluator-Optimizer loop
    Self-Correction Loop: Generator agent produces artifact; Critic/Evaluator agent runs unit tests or checks criteria; if failed, feedback is returned to Generator for iterative refinement until passing or max retry budget reached.
    🎬YT🌐G
4.2

Tool Design

4 concepts
Tools your agent calls.
  1. ☆
    Function/tool calling schema
    Schema Definition: Precise JSON Schema definitions for function inputs and outputs. Specify required fields, type constraints, enums, and clear docstrings. Avoid overly broad or nested input structures.
    🎬YT🌐G
  2. ☆
    Tool descriptions (clear, concise)
    Description Engineering: The tool description is a prompt instructing the LLM when, why, and how to use the tool. Include clear guidance on tool boundaries, parameter semantics, and sample inputs.
    🎬YT🌐G
  3. ☆
    Error handling in tools
    Defensive Execution: Tools must catch runtime exceptions and return structured, human-readable error messages ('Error: Table users does not exist. Did you mean user_accounts?') enabling the agent to self-correct rather than crashing.
    🎬YT🌐G
  4. ☆
    MCP (Model Context Protocol)
    Model Context Protocol: Open standard protocol created by Anthropic in 2024 defining a standardized JSON-RPC 2.0 communication layer between LLM clients and local/remote tool, prompt, and resource providers.
    🎬YT🌐G

Agent Frameworks

5 concepts
Popular libraries.
  1. ☆
    LangChain / LangGraph
    Stateful Workflow Graph: LangChain's graph-based orchestration framework (LangGraph). Models agent state as a cyclical state machine with explicit persistence, checkpoints, human-in-the-loop approvals, and time-travel debugging.
    🎬YT🌐G
  2. ☆
    LlamaIndex
    Data Framework: Specialized for ingestion, indexing, and querying private data. Offers hierarchical indices, query routing engines, and document agents optimized for data retrieval pipelines.
    🎬YT🌐G
  3. ☆
    DSPy
    Programmatic Prompts: Replaces manual prompt strings with declarative Python modules. Uses teleprompters (optimizers) to automatically compile and optimize prompt demonstrations and few-shot exemplars against an objective metric.
    🎬YT🌐G
  4. ☆
    Crew AI / AutoGen (multi-agent)
    Collaborative Agents: Multi-agent orchestration frameworks (CrewAI, AutoGen) simulating conversational interactions between autonomous role-playing agents. Prone to token explosion and non-deterministic loops; requires strict guardrails.
    🎬YT🌐G
  5. ☆
    Vanilla SDK (recommended for production)
    Production Architecture: Industry consensus for production agents: avoid monolithic abstraction frameworks in favor of raw provider SDKs (OpenAI, Anthropic) wrapped in clean, deterministic Python/Go loops with explicit state management.
    🎬YT🌐G

5.1

Evaluation Approaches

5 concepts
How to score LLM outputs.
  1. ☆
    Reference-based metrics (BLEU, ROUGE)
    Lexical Metrics: BLEU: Precision of n-gram overlaps (standard in machine translation). ROUGE: Recall of n-gram overlaps (standard in summarization). Brittle for open-ended LLM outputs because they penalize valid semantic paraphrasing.
    🎬YT🌐G
  2. ☆
    Reference-free metrics (perplexity, embedding sim)
    Model-Based Scoring: Perplexity: Exponential of cross-entropy loss, measures how surprised a language model is by text. Embedding Distance: Cosine distance between candidate and reference embeddings. Fast, reference-free, but blind to factual contradictions.
    🎬YT🌐G
  3. ☆
    LLM-as-judge
    Automated Judge: Prompts a frontier model (GPT-4o, Claude 3.5 Sonnet) with a detailed grading rubric to score candidate answers. Mitigations: Mitigate position bias by swapping candidate order; use chain-of-thought grading; calibrate against human judgements.
    🎬YT🌐G
  4. ☆
    Human evaluation

    Task-specific assertions
    Deterministic Assertions: Programmatic unit checks: JSON schema validation, regex pattern matching, Python code execution in sandboxes, and SQL execution assertions against test databases. Fast, reliable, and free.

6.1

Fine-tuning approaches

6 concepts
Methods from cheapest to most expensive.
  1. ☆
    Prompt tuning (soft prompts)
    Soft Prompts: Prepends learnable continuous embedding vectors to frozen model inputs. Requires negligible training memory, but exhibits lower expressivity and cannot generalize across distinct task paradigms.
    🎬YT🌐G
  2. ☆
    LoRA / QLoRA
    LoRA & QLoRA: LoRA: Freezes base weights W0 ∈ R^(d×k) and injects trainable rank decomposition matrices: ΔW = (B × A) * (α / r), where r ≪ min(d,k), cutting trainable parameters by 99%. QLoRA: Quantizes base model to 4-bit NormalFloat (NF4), adds Double Quantization and Paged Optimizers, enabling fine-tuning of 70B models on a single 48GB GPU.
    🎬YT🌐G
  3. ☆
    Full fine-tuning
    Full Parameter Updates: Modifies 100% of network weights using distributed backpropagation (DeepSpeed ZeRO-3, FSDP). Highly resource-intensive, risks catastrophic forgetting of general reasoning, and requires high learning rate warmup schedules.
    🎬YT🌐G
  4. ☆
    Instruction tuning (SFT)
    Instruction Alignment: Fine-tunes a pretrained base model on conversational (instruction, response) datasets. Transforms raw next-token completion engines into steerable assistant models that adhere to safety and system guidelines.
    🎬YT🌐G
  5. ☆
    Preference tuning (DPO, IPO, KTO)
    Preference Optimization: Aligns model outputs with human preference pairs (chosen vs rejected) using DPO, KTO (Kahneman-Tversky Optimization), or ORPO. Eliminates the complex reinforcement learning reward models of legacy PPO pipelines.
    🎬YT🌐G
  6. ☆
    When to fine-tune vs prompt vs RAG
    Decision Matrix: Prompting: First choice for 80% of tasks; instant iteration. RAG: Required for dynamic, private, or real-time factual knowledge. Fine-Tuning: Best for teaching style, tone, rigid output schemas, specialized syntax, or latency reduction via distillation into smaller models. Never fine-tune solely to inject factual data.
    🎬YT🌐G
6.2

Data + Training Infrastructure

4 concepts
Practical concerns.
  1. ☆
    Dataset preparation (quality > quantity)
    Data Quality over Volume: The LIMA paper demonstrated that 1,000 meticulously curated, high-diversity training examples produce superior conversational alignment compared to 100,000 noisy, scraped examples. Deduplicate and filter rigorously.
    🎬YT🌐G
  2. ☆
    Hyperparameters (LR, batch size, epochs)
    Hyperparameters: Learning rate: 1e-4 to 2e-4 for LoRA, 1e-5 to 5e-6 for full fine-tuning with cosine decay schedule; Batch size: 32-128; Epochs: 2-4 (avoid overfitting); LoRA rank r=8-64, alpha=16-128 (typically alpha = 2 * r).
    🎬YT🌐G
  3. ☆
    Distributed training (DeepSpeed, FSDP)
    Distributed Training: FSDP (Fully Sharded Data Parallel): Shards model weights, gradients, and optimizer states across GPUs. ZeRO (Zero Redundancy Optimizer): ZeRO-1 shards optimizer states, ZeRO-2 adds gradients, ZeRO-3 shards model parameters, eliminating memory duplication.
    🎬YT🌐G
  4. ☆
    Quantization (GGUF, AWQ, GPTQ)
    Quantization Formats: GGUF: CPU/GPU format for llama.cpp. AWQ / GPTQ: 4-bit weight-only quantization algorithms with activation-aware outlier protection, preserving near FP16 perplexity with 3x faster memory bandwidth.
    🎬YT🌐G

Performance

5 concepts
Latency and cost optimization.
  1. ☆
    Streaming responses (SSE)
    Streaming (SSE): Server-Sent Events stream generated tokens chunk-by-chunk over HTTP/2, reducing perceived Time-to-First-Token (TTFT) from several seconds to 200-400ms, drastically improving user experience.
    🎬YT🌐G
  2. ☆
    Prompt caching (Anthropic, OpenAI)
    Prefix Caching: Caches precomputed KV-cache states for shared prompt prefixes (e.g. system instructions, static RAG context). Reduces Time-to-First-Token by up to 80% and cuts API input token costs by 50-90% on OpenAI and Anthropic.
    🎬YT🌐G
  3. ☆
    Model routing (cheap → expensive)
    Tiered Cascades: Evaluates incoming queries with a fast, cheap model (e.g. GPT-4o-mini, Claude 3.5 Haiku); inspects output confidence or perplexity; escalates complex or uncertain queries to a flagship frontier model. Saves 60-80% of operational inference spend.
    🎬YT🌐G
  4. ☆
    Batching requests
    Batching & Dynamic Batching: Offline Batching: Non-interactive tasks submitted via batch APIs for 50% discount. Continuous Batching (vLLM, TGI): Iteration-level scheduling that inserts new requests and evicts finished sequences dynamically at each token step, maximizing GPU saturation.
    🎬YT🌐G
  5. ☆
    Speculative decoding
    Speculative Decoding: A small draft model speculatively generates K tokens autoregressively; the large target model evaluates all K tokens in a single parallel forward pass using causal masking. Yields 2x-3x speedup with zero degradation in mathematical output distribution.
    🎬YT🌐G

8.1

Supervised Learning

7 concepts
Labeled data → prediction.
  1. ☆
    Linear & Logistic Regression
    Foundations: Linear Regression: Solves OLS closed-form normal equation β = (X^T X)^(-1) X^T y or minimizes MSE via gradient descent; assumes linearity, homoscedasticity, and normal residuals. Logistic Regression: Models log-odds via sigmoid link σ(z) = 1 / (1 + e^(-z)); optimized via Maximum Likelihood Estimation with binary cross-entropy loss.
    🎬YT🌐G
  2. ☆
    Decision Trees
    Greedy Partitioning: Non-parametric recursive binary splitting selecting feature and split threshold maximizing Information Gain (Entropy reduction) or minimizing Gini Impurity: Gini = 1 - Σ p_i². Highly interpretable; prone to high variance and overfitting unless constrained by max depth, min samples per leaf, or cost-complexity pruning.
    🎬YT🌐G
  3. ☆
    Random Forest
    Bagging Ensemble: Bootstrap Aggregation: Trains B independent deep decision trees on random bootstrap subsets of data with random feature subsampling (typically √p features). Drastically reduces prediction variance without increasing bias; Out-Of-Bag (OOB) samples provide unbiased validation without explicit holdout sets.
    🎬YT🌐G
  4. ☆
    Gradient Boosting (XGBoost, LightGBM, CatBoost)
    Boosting Frameworks: Trains an additive sequence of shallow decision trees, where each tree fits the negative gradient (pseudo-residuals) of the loss function. XGBoost: Second-order Taylor expansion with exact Hessian weighting and tree regularization. LightGBM: Histogram binning and Gradient-based One-Side Sampling (GOSS). CatBoost: Symmetric oblivious trees and target statistics.
    🎬YT🌐G
  5. ☆
    Support Vector Machines (SVM)
    Max-Margin Separation: Finds optimal separating hyperplane maximizing geometric margin 2 / ||w|| subject to correct classification constraints. Soft-margin introduces slack variables ξ_i with penalty C. Kernel Trick: Implicitly maps data into infinite-dimensional Hilbert space via RBF kernel K(x, x') = exp(-γ ||x - x'||²).
    🎬YT🌐G
  6. ☆
    k-Nearest Neighbors (kNN)
    Instance-Based Learning: Non-parametric lazy learner storing training instances directly; classifies new queries based on majority label of k nearest neighbors in Euclidean or Manhattan distance. Inefficient at inference (O(N × D)); severely degraded by the curse of dimensionality in high dimensions without PCA.
    🎬YT🌐G
  7. ☆
    Naive Bayes
    Probabilistic Classifier: Computes posterior probability via Bayes' Rule: P(C|X) ∝ P(C) Π P(x_i|C), assuming conditional independence of features given the class. Extremely fast, robust to irrelevant features, and provides a strong baseline for high-dimensional text classification and spam detection.
    🎬YT🌐G
8.2

Unsupervised Learning

5 concepts
Unlabeled data.
  1. ☆
    k-Means clustering
    Centroid Clustering: Iterative Lloyd's algorithm: 1. Assign points to nearest centroid in Euclidean space; 2. Recalculate centroids as the arithmetic mean of assigned points. Sensitive to initialization (mitigated by k-means++ distance-weighted seeding); finds spherical clusters, requires pre-specifying k via Elbow method or Silhouette score.
    🎬YT🌐G
  2. ☆
    Hierarchical clustering
    Hierarchical Dendrograms: Agglomerative (bottom-up) clustering starting with individual points as clusters, iteratively merging closest pairs based on linkage criteria (Ward's minimum variance, complete linkage, single linkage). Produces an interpretable dendrogram tree without pre-specifying cluster counts.
    🎬YT🌐G
  3. ☆
    DBSCAN
    Density-Based Clustering: Groups dense core points with ≥ MinPts within an ε-neighborhood; expands clusters along density-connected paths. Automatically identifies arbitrary non-convex cluster shapes and isolates low-density points as explicit noise outliers.
    🎬YT🌐G
  4. ☆
    PCA (dimensionality reduction)
    Linear Dimensionality Reduction: Orthogonal linear projection onto directions of maximum variance. Mathematically equivalent to computing eigenvectors of the feature covariance matrix X^T X. Preserves global variance structure while compressing feature dimensionality.
    🎬YT🌐G
  5. ☆
    t-SNE & UMAP (visualization)
    Non-Linear Manifold Projection: t-SNE: Minimizes KL divergence between student-t distribution in low dimensions and Gaussian distribution in high dimensions; preserves local neighborhoods for visualization. UMAP: Fuzzy simplicial sets based on Riemannian geometry; faster runtime and preserves both local and global topological structure.
    🎬YT🌐G
8.3

Model Evaluation

6 concepts
Pick the right metric, avoid leakage.
  1. ☆
    Train/val/test splits
    Data Partitioning: Train / Validation / Test holdouts (e.g. 70/15/15). Stratified splits ensure identical target class proportions across folds. For time-series, temporal walk-forward splitting is mandatory to prevent future lookahead leakage.
    🎬YT🌐G
  2. ☆
    k-Fold cross-validation
    Cross-Validation: Partitions dataset into K equal disjoint folds. Iteratively trains on K-1 folds and evaluates on the remaining fold, rotating K times. Averages metric across iterations to produce an unbiased estimate of generalization performance with variance confidence intervals.
    🎬YT🌐G
  3. ☆
    Classification metrics (accuracy, F1, AUC)
    Classification Metrics: Accuracy is misleading under class imbalance. Precision: TP / (TP + FP) (minimizes false alarms). Recall: TP / (TP + FN) (minimizes missed detections). F1: Harmonic mean. ROC-AUC: Threshold-independent ranking ability. PR-AUC: Critical when positive class is rare (<1%).
    🎬YT🌐G
  4. ☆
    Regression metrics (MAE, RMSE, R²)
    Regression Metrics: MAE: Mean Absolute Error (L1 loss: predicts median, robust to extreme outliers). RMSE: Root Mean Squared Error (L2 loss: predicts mean, heavily penalizes large errors). R²: Coefficient of determination measuring proportion of target variance explained by model.
    🎬YT🌐G
  5. ☆
    Bias-variance tradeoff
    Error Decomposition: Expected Error = Bias² + Variance + Irreducible Noise. High Bias (underfitting) fails to capture underlying patterns; addressed by adding model complexity. High Variance (overfitting) models training noise; addressed by regularization, pruning, or bagging ensembles.
    🎬YT🌐G
  6. ☆
    Data leakage (the #1 silent killer)
    Data Leakage Prevention: Information from target or test split inadvertently contaminating the training feature pipeline. Golden Rule: All transformations (StandardScaler, Imputer, Target Encoding) MUST fit strictly on the training partition and only transform the test partition. Never scale before splitting.
    🎬YT🌐G
8.4

Feature Engineering

5 concepts
Where most ML gains come from.
  1. ☆
    Numeric features (scaling, log, binning)
    Continuous Transformations: StandardScaler: Zero mean, unit variance (x - μ) / σ (for gradient-based models). MinMaxScaler: Bounds to [0,1]. Log1p: Compresses long-tailed right-skewed distributions. Quantile Binning: Discretizes non-linear continuous features into equal-frequency ordinal buckets.
    🎬YT🌐G
  2. ☆
    Categorical encoding (one-hot, target, embedding)
    Categorical Transformations: One-Hot: Binary dummy indicators for low cardinality (<10). Target Encoding: Replaces category with target mean smoothed by empirical Bayes prior (prevents overfitting high-cardinality IDs). Entity Embeddings: Learns dense d-dimensional vectors in neural networks.
    🎬YT🌐G
  3. ☆
    Text features (TF-IDF, embeddings)
    Text Representations: TF-IDF: TF(t, d) × log(N / DF(t)) discounts frequent stopwords while highlighting discriminative domain keywords. Sentence Embeddings: Pretrained bi-encoders mapping phrases into semantic vector spaces.
    🎬YT🌐G
  4. ☆
    Missing value strategies
    Imputation Mechanics: Characterize missingness (MCAR vs MAR). Simple: Mean/median imputation paired with an explicit binary missingness indicator column (is_missing). Advanced: Iterative chained equations (MICE) or kNN imputation. Tree models (XGBoost) learn default split directions for missing values natively.
    🎬YT🌐G
  5. ☆
    Feature selection
    Selection Methods: Filter: Pearson/Spearman correlation or mutual information ranking. Wrapper: Recursive Feature Elimination (RFE) pruning weakest features iteratively. Embedded: L1 Lasso penalty driving coefficients to zero, performing intrinsic feature selection.
    🎬YT🌐G

9.1

Core Concepts

6 concepts
What makes a neural net learn.
  1. ☆
    Backpropagation & gradient descent
    Reverse-Mode Differentiation: Computes exact partial derivatives ∂L / ∂W using the multivariable chain rule on directed acyclic computational graphs. Forward pass computes intermediate activations; backward pass propagates adjoint gradient vectors from loss to parameters.
    🎬YT🌐G
  2. ☆
    Activation functions (ReLU, GELU, Swish)
    Non-Linear Mappings: Introduces representational capacity to multi-layer networks. ReLU: max(0, x) (fast, mitigates vanishing gradients, suffers from dying ReLU). GELU: x Φ(x) (smooth Gaussian error gating, standard in BERT and GPT). Swish/SiLU: x σ(βx) (used in LLaMA architectures).
    🎬YT🌐G
  3. ☆
    Loss functions
    Optimization Objectives: Cross-Entropy: -Σ y_i log(p_i) for classification (minimizes KL-divergence between empirical and predicted distributions). MSE / Huber Loss: For continuous regression. InfoNCE / Contrastive: Maximizes similarity of positive pairs against negative batches in metric embedding learning.
    🎬YT🌐G
  4. ☆
    Optimizers (SGD, Adam, AdamW)
    Adaptive Optimization: SGD with Momentum: Accelerates through ravines by accumulating past velocity. Adam: Combines first-moment momentum and second-moment uncentered variance estimation. AdamW: Decouples L2 weight decay from gradient updates, resolving weight magnitude decay issues in Transformers.
    🎬YT🌐G
  5. ☆
    Regularization (dropout, weight decay, augmentation)
    Generalization Guards: Dropout: Randomly zeroes activations with probability p during training, simulating an exponential ensemble of sub-networks. Weight Decay: Penalizes large L2 weight norms 0.5 λ ||W||². Data Augmentation: Mixup and CutMix forcing invariant representations.
    🎬YT🌐G
  6. ☆
    Batch normalization
    Normalization Mechanics: Batch Normalization: Normalizes across mini-batch dimension; unstable with small batches and autoregressive sequences. Layer Normalization: Normalizes across feature channels for each token independently: (x - μ) / √(σ² + ε) × γ + β. Indispensable for sequence stability.
    🎬YT🌐G
9.2

Architectures

5 concepts
Family of models per problem.
  1. ☆
    CNNs (computer vision)
    Spatial Feature Extraction: Leverages discrete 2D convolutions with weight sharing and local receptive fields to encode translation-invariant patterns. ResNet: Introduced identity shortcut connections F(x) + x, enabling training of 100+ layer networks without gradient degradation.
    🎬YT🌐G
  2. ☆
    RNNs / LSTMs (sequence, mostly historical)
    Recurrent State Updates: Processes sequences sequentially: h_t = tanh(W_h h_(t-1) + W_x x_t). LSTM: Introduces constant error carousel cell states governed by Forget, Input, and Output gates, mitigating vanishing gradients but constrained by non-parallelizable sequential execution.
    🎬YT🌐G
  3. ☆
    Transformers (covered in section 1)
    Attention Supremacy: Replaces recurrence with parallel self-attention mechanisms. Modern Vision Transformers (ViT) divide images into 16x16 flattened patches, projecting them into transformer token embeddings to outperform CNNs on large datasets without spatial inductive bias.
    🎬YT🌐G
  4. ☆
    Diffusion models (image generation)
    Iterative Denoising: Generative models formulating generation as reversing a thermodynamic diffusion process. Forward process incrementally injects Gaussian noise into data; reverse process trains a U-Net or DiT (Diffusion Transformer) to predict and subtract noise at timestep t (DDPM, Flow Matching).
    🎬YT🌐G
  5. ☆
    Mixture of Experts (MoE)
    Sparse Activation: Replaces dense feed-forward blocks with E parallel expert networks. A parameterized gating router computes a softmax distribution over experts, routing each token to only the top-k experts (e.g. Mixtral 8x7B activates 2 of 8 experts per token), scaling capacity with constant FLOPs.
    🎬YT🌐G

How to serve models.

Monitoring

4 concepts
Watch for decay.
  1. ☆
    Data drift detection
    Input Distribution Shift: Detects when inference feature distributions drift from training data P(X). Employs statistical tests: Kolmogorov-Smirnov (KS) test for numerical variables, Population Stability Index (PSI > 0.2 flags severe drift), and Earth Mover's Distance.
    🎬YT🌐G
  2. ☆
    Concept drift
    Relationship Shift: Detects shifts in the relationship between input features and target labels P(Y|X) (e.g. macro changes in user purchasing habits). Requires delayed ground truth labels; tracked via rolling accuracy/F1 windows.
    🎬YT🌐G
  3. ☆
    Model performance monitoring
    Inference Telemetry: Real-time observability tracking model throughput (QPS), p50/p95/p99 inference latency, GPU memory/utilization, token consumption rates, and prediction distribution entropy via Prometheus and Grafana.
    🎬YT🌐G
  4. ☆
    Logging predictions + features
    Data Flywheel: Asynchronous logging of production inference payloads (features, predictions, latency) with PII redaction to data lakes. Samples low-confidence predictions to feed active learning and fine-tuning pipelines.
    🎬YT🌐G

Structured Outputs & Tool Calling

5 concepts
Making model output machine-reliable.
  1. ☆
    JSON mode and schema-constrained decoding
    CFG / Regex logit masking at each token step guarantees 100% valid JSON schema compliance at generation time with zero parsing errors.
    🎬YT🔍G
  2. ☆
    Function calling APIs
    Model emits tool name and JSON args matching OpenAPI schemas; client runtime executes and returns results as tool-role messages for final synthesis.
    🎬YT🔍G
  3. ☆
    Tool selection and routing
    Keep tool definitions minimal and discriminative; tool descriptions are prompts guiding the model on boundaries, inputs, and operational side effects.
    🎬YT🔍G
  4. ☆
    Parallel tool calls
    Independent tool calls batched in a single turn reduce multi-turn roundtrip latency by up to 75% for read-heavy agent workflows.
    🎬YT🔍G
  5. ☆
    Validating and repairing output
    Pydantic validation with automated repair loops feeding execution tracebacks and validation errors back to the model for iterative correction.
    🎬YT🔍G
11.2

RAG Evaluation

4 concepts
Proving retrieval actually works.
  1. ☆
    Retrieval metrics (recall@k, MRR)
    Recall@K measures chunk presence in top-K; Mean Reciprocal Rank (MRR) evaluates ranking position of first relevant chunk across evaluation queries.
    🎬YT🔍G
  2. ☆
    Faithfulness and groundedness
    Evaluates whether claims in generated answer are mathematically supported by retrieved context via LLM-as-a-judge (Ragas framework).
    🎬YT🔍G
  3. ☆
    Golden datasets and synthetic evals
    Curate 50-200 ground-truth Q-A-Context triples; bootstrap adversarial edge cases with synthetic question generation across diverse document domains.
    🎬YT🔍G
  4. ☆
    End-to-end RAG eval pipelines
    Decouple retrieval evaluation (Hit Rate, MRR, Context Relevance) from generation evaluation (Faithfulness, Groundedness) to isolate pipeline failures.
    🎬YT🔍G
11.3

Agent Reliability

4 concepts
Agents that don't run off the rails.
  1. ☆
    Agent failure modes
    Infinite tool calling loops, hallucinated arguments, context window overflow, and goal drift. Mitigate with hard step caps, timeouts, and state checkpoints.
    🎬YT🔍G
  2. ☆
    Guardrails on actions and budgets
    Step limits (max 10 iterations), per-session token/spend budgets, strict tool allowlists, and dry-run execution modes for mutations.
    🎬YT🔍G
  3. ☆
    Human-in-the-loop checkpoints
    Mandatory human review and approval gates before executing high-blast-radius actions (database writes, refunds, customer communications).
    🎬YT🔍G
  4. ☆
    Tracing agent decisions
    OpenTelemetry-compatible step-by-step tracing (Langfuse, LangSmith) capturing thoughts, tool calls, return values, latency, and token cost.
    🎬YT🔍G

Safety & Guardrails

4 concepts
Defense in depth for LLM apps.
  1. ☆
    Input and output content filtering

11.7

Cost & Latency Optimization

5 concepts
Unit economics of LLM features.
  1. ☆
    Model routing and cascades
    Route incoming requests to smaller cheap models (GPT-4o-mini, Haiku); escalate to frontier models only on low confidence or high complexity.
    🎬YT🔍G
  2. ☆
    Caching (exact and semantic)
    Exact hash caching for identical prompt strings; vector embedding semantic caching (>=0.95 cosine similarity) for common queries.
    🎬YT🔍G
  3. ☆
    Batching and streaming
    Server-Sent Events (SSE) for low TTFT online queries; asynchronous batch API processing for offline jobs at 50% discount.
    🎬YT🔍G
  4. ☆
    Quantization and distillation
    AWQ / GPTQ 4-bit weight quantization and knowledge distillation from frontier models into specialized 8B/70B models for on-prem serving.
    🎬YT🔍G
  5. ☆
    Context window budgeting
    Dynamic context truncation, hierarchical summarization, and vector retrieval filtering to prevent prompt bloat and 'Lost in the Middle' degradation.
    🎬YT🔍G
