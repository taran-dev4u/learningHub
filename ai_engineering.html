Transformers & Attention

5 concepts
The architecture behind GPT, Claude, etc.
  1. ☆
    Self-attention mechanism
    Each token attends to others; weights are learned. The 'aha' of transformers.
    🔍YT🔍G
  2. ☆
    Multi-head attention
    Parallel attention 'heads' learn different relationships.
    🔍YT🔍G
  3. ☆
    Positional encoding (sinusoidal, RoPE)
    How transformers know word order. RoPE used in modern LLMs.
    🔍YT🔍G
  4. ☆
    Encoder vs decoder vs encoder-decoder
    BERT = encoder. GPT = decoder. T5 = both. Different tasks.
    🔍YT🔍G
  5. ☆
    Layer normalization & residual connections
    Training stability + deeper networks.
    🔍YT🔍G

Tokens & Tokenization

4 concepts
Text → numbers. The interface.
  1. ☆
    Byte-Pair Encoding (BPE)
    Subword units. GPT tokenizer. ~4 chars per token avg.
    🔍YT🔍G
  2. ☆
    Tokenizer behavior (whitespace, unicode)
    Leading spaces, casing, special chars all matter for cost + quality.
    🔍YT🔍G
  3. ☆
    Context window limits
    GPT-4o: 128K. Claude: 200K+. Costs scale with context length.
    🔍YT🔍G
  4. ☆
    Token cost optimization
    Strip whitespace, compress prompts, cache common prefixes.
    🔍YT🔍G

Training & Inference

6 concepts
How models learn and respond.
  1. ☆
    Pretraining (next-token prediction)
    Trillions of tokens, autoregressive objective. Trillions of FLOPs.
    🔍YT🔍G
  2. ☆
    Supervised fine-tuning (SFT)
    Train on input-output pairs. Makes model follow instructions.
    🔍YT🔍G
  3. ☆
    RLHF (Reinforcement Learning from Human Feedback)
    Reward model trained from human preferences. Then PPO/DPO. Makes models helpful + harmless.
    🔍YT🔍G
  4. ☆
    DPO (Direct Preference Optimization)
    Simpler RLHF alternative. No separate reward model.
    🔍YT🔍G
  5. ☆
    Inference: temperature, top-p, top-k
    Temperature = randomness. Top-p = nucleus sampling. Top-k = limit choices.
    🔍YT🔍G
  6. ☆
    Sampling strategies
    Greedy, beam search, top-p, temperature. Determines output diversity.
    🔍YT🔍G

Core Techniques

7 concepts
What every prompt engineer knows.
  1. ☆
    Zero-shot prompting
    Ask without examples. Works for most tasks today.
    🔍YT🔍G
  2. ☆
    Few-shot prompting
    Include 2-5 input/output examples. Improves consistency.
    🔍YT🔍G
  3. ☆
    Chain-of-Thought (CoT)
    'Let's think step by step.' Major gains on reasoning tasks.
    🔍YT🔍G
  4. ☆
    Self-consistency
    Sample multiple CoT outputs, take majority vote.
    🔍YT🔍G
  5. ☆
    Tree of Thoughts (ToT)
    Explore reasoning as a tree. For complex search problems.
    🔍YT🔍G
  6. ☆
    ReAct (Reason + Act)
    Interleave reasoning with tool calls.
    🔍YT🔍G
  7. ☆
    System prompts vs user prompts
    System: persistent role, rules. User: turn-by-turn requests.
    🔍YT🔍G

RAG Pipeline Stages

7 concepts
End-to-end flow.
  1. ☆
    Document loading & parsing
    PDFs, web, code, tables. Quality of input drives quality of output.
    🔍YT🔍G
  2. ☆
    Chunking strategies
    Fixed-size, sentence, semantic, recursive. ~500-1000 tokens typical.
    🔍YT🔍G
  3. ☆
    Embeddings (sentence-transformers, OpenAI ada)
    Text → vectors. Semantic similarity = cosine distance.
    🔍YT🔍G
  4. ☆
    Vector storage & ANN search
    HNSW, IVF, scaNN. Approximate nearest neighbor.
    🔍YT🔍G
  5. ☆
    Retrieval (dense, sparse, hybrid)
    Dense = embeddings. Sparse = BM25/keyword. Hybrid = best of both.
    🔍YT🔍G
  6. ☆
    Reranking (Cohere, cross-encoder)
    Second-pass model to refine top-K results. Big quality jump.
    🔍YT🔍G
  7. ☆
    Prompt construction with retrieved context
    Include sources, citation markers, instructions to ground.
    🔍YT🔍G

Beyond naive RAG.
  1. ☆
    Query rewriting / decomposition
    Use LLM to rephrase user query before retrieval.

Agent Patterns

    Orchestrator-Workers
    Central agent dispatches to specialized worker agents.

    Evaluator-Optimizer loop

5.1

Evaluation Approaches

5 concepts
How to score LLM outputs.
  1. ☆
    Reference-based metrics (BLEU, ROUGE)
    Compare to ground-truth. Mostly outdated for open generation.
    🔍YT🔍G
  2. ☆
    Reference-free metrics (perplexity, embedding sim)
    No ground truth needed. Limited signal.
    🔍YT🔍G
  3. ☆
    LLM-as-judge
    Use a model to grade outputs. GPT-4 grading is common. Cheap, biased.
    🔍YT🔍G
  4. ☆
    Human evaluation
    Gold standard, expensive. SxS comparisons, Likert scales.
    🔍YT🔍G
  5. ☆
    Task-specific assertions
    Code: does it compile/pass tests? SQL: does query return same row count? JSON: validates against schema?
    🔍YT🔍G
5.2

Build an Eval Pipeline

5 concepts
Practical workflow.
  1. ☆
    Eval set construction (start with 50-100 examples)
    Hand-curated, diverse. Update as bugs emerge.
    🔍YT🔍G
  2. ☆
    Regression testing on every prompt change
    Treat prompts like code. CI runs evals on every PR.
    🔍YT🔍G
  3. ☆
    A/B testing in production
    Compare prompt v1 vs v2 on real traffic. Statistical significance.
    🔍YT🔍G
  4. ☆
    Continuous monitoring (Langfuse, LangSmith)
    Trace every prod call, sample for eval, flag regressions.
    🔍YT🔍G
  5. ☆
    Red-teaming for safety/jailbreaks
    Adversarial testing. OWASP Top 10 for LLMs.

6.1

Fine-tuning approaches

6 concepts
Methods from cheapest to most expensive.
  1. ☆
    Prompt tuning (soft prompts)
    Learn embeddings only, freeze model. Few parameters.
    🔍YT🔍G
  2. ☆
    LoRA / QLoRA
    Train low-rank adapters. QLoRA quantizes base model. Standard approach.
    🔍YT🔍G
  3. ☆
    Full fine-tuning
    Update all weights. Expensive, risks catastrophic forgetting.
    🔍YT🔍G
  4. ☆
    Instruction tuning (SFT)
    Train on (instruction, response) pairs. Makes models follow directions.
    🔍YT🔍G
  5. ☆
    Preference tuning (DPO, IPO, KTO)
    Train on preference pairs. Simpler than full RLHF.
    🔍YT🔍G
  6. ☆
    When to fine-tune vs prompt vs RAG
    Fine-tune for: format, tone, niche domain, latency. Don't for: new facts (use RAG).
    🔍YT🔍G
6.2

Data + Training Infrastructure

4 concepts
Practical concerns.
  1. ☆
    Dataset preparation (quality > quantity)
    1000 high-quality examples > 100K noisy. LIMA paper showed this.
    🔍YT🔍G
  2. ☆
    Hyperparameters (LR, batch size, epochs)
    LR ~1e-4 for LoRA. 2-5 epochs typical.
    🔍YT🔍G
  3. ☆
    Distributed training (DeepSpeed, FSDP)
    Multi-GPU/multi-node training. Memory savings.
    🔍YT🔍G
  4. ☆
    Quantization (GGUF, AWQ, GPTQ)
    4-bit/8-bit weights. Smaller, faster inference.
    🔍YT🔍G

Performance

    Streaming responses (SSE)

    Batching requests
    Send multiple in parallel. Provider rate limits matter.

    Speculative decoding

    🔍YT🔍G

Model Evaluation

6 concepts
Pick the right metric, avoid leakage.
  1. ☆
    Train/val/test splits
    Time-based for time-series. Stratified for imbalanced classes.
    🔍YT🔍G
  2. ☆
    k-Fold cross-validation
    More robust estimate. Use stratified K-fold for classification.
    🔍YT🔍G
  3. ☆
    Classification metrics (accuracy, F1, AUC)
    Accuracy lies for imbalanced data. F1, ROC-AUC, PR-AUC better.
    🔍YT🔍G
  4. ☆
    Regression metrics (MAE, RMSE, R²)
    RMSE penalizes large errors. MAE robust to outliers.
    🔍YT🔍G
  5. ☆
    Bias-variance tradeoff
    High bias = underfit. High variance = overfit.
    🔍YT🔍G
  6. ☆
    Data leakage (the #1 silent killer)
    Future info in training. Target leakage. Group leakage. Audit ruthlessly.
    🔍YT🔍G
