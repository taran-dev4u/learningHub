# Delivery Semantics &amp; Reliability

## Overview
Welcome to the module on **Delivery Semantics &amp; Reliability**. This page covers the following related subtopics:

- At-most-once — fire and forget, may lose messages
- At-least-once — retry on failure, duplicates possible → make consumers idempotent
- Exactly-once — Kafka transactions or idempotency keys
- Idempotency keys — safe retries, critical for payments (Airbnb, Stripe)
- Dead Letter Queue (DLQ) — park failed messages after N retries for inspection
