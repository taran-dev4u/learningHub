Cloud Models

3 concepts
IaaS / PaaS / SaaS and public/private/hybrid.
  1. ☆
    IaaS vs PaaS vs SaaS
    IaaS: you manage OS+. PaaS: managed runtime. SaaS: full app. More you delegate, less you control.
    🔍YT🔍G
  2. ☆
    Public vs Private vs Hybrid Cloud
    Public: AWS/Azure shared infra. Private: your own DC. Hybrid: both.
    🔍YT🔍G
  3. ☆
    Cloud economics: pay-as-you-go + elasticity
    No upfront capex. Scale out on demand, down when quiet. Cost = usage × unit price.
    🔍YT🔍G

Global Infrastructure

4 concepts
Regions, AZs, edge.
  1. ☆
    Region
    Geographic cluster of data centers. AWS ~30+, Azure ~60+. Pick by latency + compliance.
    🔍YT🔍G
  2. ☆
    Availability Zone (AZ)
    One or more isolated DCs in a region. Deploy across ≥2 AZs for high availability.
    🔍YT🔍G
  3. ☆
    Edge locations / PoPs
    CDN and DNS endpoints near users. Hundreds worldwide.
    🔍YT🔍G
  4. ☆
    How to pick a region
    Factors: latency to users, data residency law (GDPR), service availability, price differences.
    🔍YT🔍G

2.1

Identity primitives

4 concepts
What gets authenticated.
  1. ☆
    IAM Users / Groups / Roles (AWS)
    User = person/service with creds. Group = collection of users. Role = assumable identity (best practice for services).
    🔍YT🔍G
  2. ☆
    Managed Identity (Azure) / IAM Role for EC2 (AWS)
    Auto-rotating credentials attached to a workload. Never embed API keys — use this instead.
    🔍YT🔍G
  3. ☆
    Federation (SAML / OIDC / SSO)
    External IdP (Okta, Active Directory) → cloud access. Single Sign-On for humans and machines.
    🔍YT🔍G
  4. ☆
    AWS Organizations / Azure Management Groups
    Multi-account / multi-subscription hierarchy. SCPs (AWS) enforce policy across all accounts.
    🔍YT🔍G
2.2

Policies & Permissions

4 concepts
How access is granted.
  1. ☆
    AWS IAM Policy (JSON: Effect / Action / Resource)
    Allow or Deny specific API actions on specific resources. Conditions for MFA, IP, time.
    🔍YT🔍G
  2. ☆
    Azure RBAC built-in roles (Owner/Contributor/Reader)
    Scope at subscription, resource group, or resource. Custom roles for granular control.
    🔍YT🔍G
  3. ☆
    Permission boundaries / Service Control Policies
    Maximum permissions ceiling regardless of individual policies. Critical for multi-account governance.
    🔍YT🔍G
  4. ☆
    Secrets Manager / Key Vault
    Store + rotate DB passwords, API keys, certs. Apps fetch at runtime — no secrets in code.

Virtual Machines

6 concepts
EC2 / Azure VMs.
  1. ☆
    Instance families (general / compute / memory / GPU)
    AWS: t/m/c/r/x/p/g/inf. Azure: B/D/F/E/M/N/H. Match workload to family.
    🔍YT🔍G

    Preconfigured OS+software snapshot. Build golden AMIs for fast, consistent launches.
    🔍YT🔍G

    Scale count based on CloudWatch/Monitor metrics. Min/desired/max.

    User Data / Cloud-init
    Bootstrap script runs on first boot. Install packages, configure services.
    🔍YT🔍G
  6. ☆
    Elastic IP / Static Public IP
    Persistent public IP that survives stop/start. Charged when unattached.
    🔍YT🔍G

Serverless

    Function invoked on events (HTTP, queue, schedule, blob change). Sub-second billing.
    🔍YT🔍G

4.1

Object Storage (S3 / Azure Blob)

7 concepts
The backbone of cloud storage.
  1. ☆
    Buckets / Containers — namespace and naming
    S3: globally unique names. Azure: storage account → container. No directory hierarchy (but prefix-based 'folders' work).
    🔍YT🔍G
  2. ☆
    Storage classes / access tiers
    S3: Standard → Intelligent-Tiering → IA → Glacier. Azure: Hot → Cool → Archive. Lifecycle rules automate transitions.
    🔍YT🔍G
  3. ☆
    Versioning + object lock
    Keep all versions. Object lock = WORM (write once, read many) for compliance.
    🔍YT🔍G
  4. ☆
    Encryption at rest (SSE-S3, SSE-KMS, CMK)
    SSE-S3: managed keys (free). SSE-KMS: customer managed in KMS ($). CMK: your own key material.
    🔍YT🔍G
  5. ☆
    Pre-signed URLs / SAS tokens
    Temporary access URLs. Allow direct browser upload/download bypassing your server.
    🔍YT🔍G
  6. ☆
    Cross-region replication
    Async replicate to another region. Used for DR, compliance, latency reduction.
    🔍YT🔍G
  7. ☆
    S3 object size limits
    Min 0 bytes. Max 5TB (single object). Multipart upload required for >5GB.
    🔍YT🔍G
4.2

Block & File Storage

4 concepts
EBS / Managed Disks + EFS / Azure Files.
  1. ☆
    EBS types: gp3 / io2 / st1 / sc1
    gp3: balanced default (baseline 3000 IOPS). io2: high-IOPS DB (up to 64k). st1/sc1: HDD for throughput/cold.
    🔍YT🔍G
  2. ☆
    EBS Snapshots
    Incremental point-in-time backup stored in S3. Use for AMI creation + DR.
    🔍YT🔍G
  3. ☆
    EFS / Azure Files — shared file system
    Mount on many instances simultaneously. NFS (EFS) or SMB (Azure Files). For shared application data.
    🔍YT🔍G
  4. ☆
    EBS vs EFS vs S3 — when to use which
    EBS: single-instance block. EFS: multi-mount NFS. S3: everything else (object, unstructured, static).
    🔍YT🔍G

5.1

VPC / VNet Basics

7 concepts
Your private network in the cloud.
  1. ☆
    CIDR blocks / address space planning
    e.g. 10.0.0.0/16 gives 65k IPs. Avoid overlapping with on-prem or other VPCs you'll peer.
    🔍YT🔍G
  2. ☆
    Public vs Private subnets
    Public subnet has route to IGW. Private subnet uses NAT Gateway for outbound (no inbound).
    🔍YT🔍G
  3. ☆
    Internet Gateway (IGW) and NAT Gateway
    IGW: bidirectional internet for public subnets. NAT: outbound-only internet for private subnets.
    🔍YT🔍G
  4. ☆
    Route Tables
    Each subnet has a route table. 0.0.0.0/0 → IGW = public. 0.0.0.0/0 → NAT = private.
    🔍YT🔍G
  5. ☆
    VPC Peering / VNet Peering
    Connect two VPCs. Non-transitive (A-B, B-C ≠ A-C). Use Transit Gateway for hub-spoke.
    🔍YT🔍G
  6. ☆
    Transit Gateway / Azure Virtual WAN
    Central hub connecting many VPCs/VNets + on-prem. Full mesh without individual peerings.
    🔍YT🔍G
  7. ☆
    VPN + Direct Connect / ExpressRoute
    VPN: encrypted over internet. DX/ExpressRoute: dedicated fibre, predictable latency.
    🔍YT🔍G
5.2

Security Controls

4 concepts
Network-level firewall.
  1. ☆
    Security Groups (AWS) — stateful, instance-level
    Allow-only. Attached to ENI/instance. Return traffic automatically allowed.
    🔍YT🔍G
  2. ☆
    NACLs (AWS) — stateless, subnet-level
    Allow + Deny. Applied to subnet. Rules evaluated in order. Return traffic needs explicit rule.
    🔍YT🔍G
  3. ☆
    NSGs (Azure) — stateful, subnet or NIC
    Like security groups. Default deny all inbound from internet.
    🔍YT🔍G
  4. ☆
    SG vs NACL key differences (AWS exam favourite)
    SG: stateful, instance, allow-only. NACL: stateless, subnet, allow+deny, numbered rules.
    🔍YT🔍G
5.3

Load Balancers & CDN

4 concepts
Traffic distribution and edge delivery.
  1. ☆
    ALB (L7 HTTP) vs NLB (L4 TCP) — AWS
    ALB: path/host routing, WebSockets, Lambda targets. NLB: extreme performance, static IP, TCP/UDP.
    🔍YT🔍G
  2. ☆
    Azure App Gateway (L7) vs Azure LB (L4)
    App Gateway: WAF, URL routing, SSL offload. Azure LB: fast TCP load distribution.
    🔍YT🔍G
  3. ☆
    CloudFront / Azure CDN / Front Door
    CDN at edge. CloudFront + S3 = static site. Front Door = global L7 LB + CDN.
    🔍YT🔍G
  4. ☆
    Route 53 routing policies
    Simple, weighted, latency-based, failover, geolocation, multivalue.
    🔍YT🔍G

6.1

Managed SQL

5 concepts
RDS / Aurora / Azure SQL.
  1. ☆
    RDS — managed MySQL/Postgres/SQL Server/Oracle
    Auto backups, patching, Multi-AZ, read replicas. You still manage schema + queries.
    🔍YT🔍G
  2. ☆
    Aurora — cloud-native SQL
    MySQL/Postgres compatible. 5x MySQL performance. Serverless v2 auto-scales to 0.
    🔍YT🔍G
  3. ☆
    Multi-AZ (Primary + standby in another AZ)
    Sync replication to standby. Auto-failover in ~60s. Use for production always.
    🔍YT🔍G
  4. ☆
    Read Replicas (async, for read scaling)
    Lag is possible. Cross-region replicas for geo-locality. Not a failover target by default.
    🔍YT🔍G
  5. ☆
    Azure SQL Database / Managed Instance
    SQL Server as a service. Managed Instance = near 100% SQL Server compatibility.
    🔍YT🔍G
6.2

NoSQL & Cache

5 concepts
DynamoDB, Cosmos DB, ElastiCache.
  1. ☆
    DynamoDB — key-value / document, infinite scale
    Single-digit ms at any scale. Pay per request. GSI for query flexibility. On-demand mode.
    🔍YT🔍G
  2. ☆
    DynamoDB — partition key design
    Hot partitions kill performance. High-cardinality keys. Composite keys for sort.
    🔍YT🔍G
  3. ☆
    Cosmos DB (Azure) — multi-model, multi-region
    5 consistency levels. Multi-region writes. SQL/MongoDB/Gremlin/Table APIs.
    🔍YT🔍G
  4. ☆
    ElastiCache / Azure Cache for Redis
    In-memory cache layer. Sub-ms. Redis for rich data types, Memcached for simple cache.
    🔍YT🔍G
  5. ☆
    Redshift / Azure Synapse — data warehouse
    Columnar storage, petabyte-scale, MPP. For analytics queries, not OLTP.
    🔍YT🔍G

Queues & Topics

5 concepts
SQS / SNS / Service Bus.
  1. ☆
    SQS Standard vs FIFO Queue
    Standard: at-least-once, best-effort order, unlimited throughput. FIFO: exactly-once, strict order, 3k TPS.
    🔍YT🔍G
  2. ☆
    SNS Topics — pub/sub fan-out
    One message → many subscribers (SQS, Lambda, HTTP, email). At-least-once.
    🔍YT🔍G
  3. ☆
    Azure Service Bus — enterprise messaging
    Queues and topics. Dead-letter queue, sessions, transactions.
    🔍YT🔍G
  4. ☆
    Dead Letter Queues (DLQ)
    After N failures, message parked for inspection. Essential for debugging poison messages.
    🔍YT🔍G
  5. ☆
    EventBridge / Azure Event Grid — event bus
    Route events by pattern to targets. Serverless, 100+ AWS sources for EventBridge.
    🔍YT🔍G
7.2

Streaming

4 concepts
Kinesis / Event Hubs / MSK.
  1. ☆
    Kinesis Data Streams (AWS)
    Real-time streaming. Shards = throughput units. 24h-7d retention. Multiple consumers.
    🔍YT🔍G
  2. ☆
    Azure Event Hubs
    Kafka-compatible event streaming. Consumer groups. Up to 90-day retention.
    🔍YT🔍G
  3. ☆
    Amazon MSK — managed Kafka
    Fully managed Kafka. Use when you need Kafka ecosystem (Kafka Connect, Streams).
    🔍YT🔍G
  4. ☆
    Kinesis vs SQS vs MSK — when to use
    SQS: work queue. Kinesis: real-time analytics/ordered. MSK: existing Kafka tooling.

8.1

Metrics & Alarms

3 concepts
CloudWatch / Azure Monitor.
  1. ☆
    CloudWatch Metrics — built-in + custom
    EC2 default: CPU, network, disk. Enable detailed monitoring for 1-min granularity. Custom metrics via PutMetricData API.
    🔍YT🔍G
  2. ☆
