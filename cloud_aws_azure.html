Cloud Models

3 concepts
IaaS / PaaS / SaaS and public/private/hybrid.
  1. ☆
    IaaS vs PaaS vs SaaS
    Cloud Delivery Models: IaaS (EC2, Azure VMs): Vendor provisions physical hardware, virtualization, and networking; you manage OS patching, runtime, middleware, and data. PaaS (Elastic Beanstalk, App Service): Vendor manages OS, runtime, and scaling; you deploy code and configuration. SaaS (Microsoft 365, Salesforce): Fully vendor-managed application.
    🔍YT🔍G
  2. ☆
    Public vs Private vs Hybrid Cloud
    Cloud Deployment Models: Public Cloud: Multi-tenant shared infrastructure partitioned via hypervisor isolation. Private Cloud: Dedicated single-tenant infrastructure on-premises (OpenStack, VMware). Hybrid Cloud: Interconnected public and private environments via Direct Connect / ExpressRoute with unified control planes (AWS Outposts, Azure Arc).
    🔍YT🔍G
  3. ☆
    Cloud economics: pay-as-you-go + elasticity
    Economics & Elasticity: Converts CapEx (capital expenditure on depreciating servers) to OpEx (operating expenditure paid on consumption). Elasticity enables dynamic scaling to match real-time load, preventing over-provisioning waste while maintaining p99 latency SLAs during unexpected traffic spikes.
    🔍YT🔍G

Global Infrastructure

4 concepts
Regions, AZs, edge.
  1. ☆
    Region
    Regions: Independent geographic areas containing multiple physically separated, isolated data centers. Designed for fault isolation; regional outages do not cascade to other regions. Cross-region communication traverses encrypted private AWS/Azure fiber backbones with low latency.
    🔍YT🔍G
  2. ☆
    Availability Zone (AZ)
    Availability Zones (AZs): One or more discrete data centers with redundant power, cooling, and low-latency (<1-2ms round-trip) interconnects within a region. Deploying active workloads across ≥3 AZs guarantees high availability against datacenter floods, fires, or power grid failures.
    🔍YT🔍G
  3. ☆
    Edge locations / PoPs
    Edge Network & Points of Presence: Hundreds of edge locations running CloudFront, Route 53, and AWS Global Accelerator worldwide. Terminates TLS at edge POPs close to end users, caches static assets, and proxies dynamic API traffic over optimized backbone links.
    🔍YT🔍G
  4. ☆
    How to pick a region
    Region Selection Criteria: 1. Data Sovereignty & Compliance: GDPR (EU), HIPAA/FedRAMP (US); 2. User Proximity: Lowest network latency for primary user demographics; 3. Service Availability: Bleeding-edge features launch in primary regions (us-east-1, eastus) first; 4. Cost Variance: Cloud pricing varies up to 20-30% between regions due to local energy and tax rates.
    🔍YT🔍G

Shared Responsibility & Well-Architected

2 concepts
Security division + design pillars.
  1. ☆
    Shared Responsibility Model
    Security Division: Cloud provider owns security OF the cloud (physical security of facilities, hardware maintenance, hypervisor patching, network infrastructure). Customer owns security IN the cloud (guest OS patching, IAM policies, firewall rules, encryption at rest/in transit, customer data).
    🔍YT🔍G
  2. ☆
    Well-Architected Framework (6 pillars)
    Well-Architected Pillars: Operational Excellence (run operations as code, evolve), Security (defense in depth, least privilege), Reliability (auto-recovery, cross-AZ redundancy), Performance Efficiency (serverless, right-sizing), Cost Optimization (FinOps, reserved capacity), Sustainability (ARM Graviton, high utilization).
    🔍YT🔍G

AWS ↔ Azure Service Mapping

30 concepts
Translate between the two clouds.
  1. ☆
    Compute / VMs: AWS 'EC2' ↔ Azure 'Azure Virtual Machines'
    AWS EC2 (Nitro hypervisor architecture with dedicated hardware offload for VPC, EBS, and crypto) vs Azure Virtual Machines (Hyper-V / Azure Boost architecture with managed ephemeral OS disks). Both offer spot/burstable/compute-optimized instances; EC2 offers more granular instance families while Azure provides tighter integration with Windows Server licensing (Hybrid Benefit).
    🔍YT🔍G
  2. ☆
    Auto Scaling: AWS 'Auto Scaling Groups' ↔ Azure 'VM Scale Sets'
    AWS Auto Scaling Groups (Launch Templates, target tracking policies, predictive scaling based on ML, step scaling) vs Azure Virtual Machine Scale Sets (VMSS, flexible vs uniform orchestration modes, autoscale rules based on CPU/RAM metrics). Both support multi-AZ spreading and spot instance mix.
    🔍YT🔍G
  3. ☆
    Containers: AWS 'ECS / EKS' ↔ Azure 'ACI / AKS'
    AWS ECS (native AWS container orchestrator with Fargate serverless compute) & EKS (upstream Kubernetes with managed control plane) vs Azure ACI (Azure Container Instances for fast serverless container execution) & AKS (Azure Kubernetes Service with free control plane tier and integrated Azure CNI networking).
    🔍YT🔍G
  4. ☆
    Container Registry: AWS 'ECR' ↔ Azure 'Azure Container Registry'
    AWS ECR (Elastic Container Registry, immutable image tags, KMS encryption, automated Trivy vulnerability scanning, cross-region replication) vs Azure Container Registry (ACR, geo-replicated container registry, private endpoints, ACR Tasks for automated container builds on git commit).
    🔍YT🔍G
  5. ☆
    Serverless: AWS 'Lambda' ↔ Azure 'Azure Functions'
    AWS Lambda (Firecracker microVM isolation, 15-minute execution limit, SnapStart for instant Java startup, event source mappings) vs Azure Functions (Consumption plan, Premium plan with pre-warmed instances, Durable Functions for stateful serverless workflows via orchestrator and entity functions).
    🔍YT🔍G
  6. ☆
    Object Storage: AWS 'S3' ↔ Azure 'Azure Blob Storage'
    AWS S3 (11 9s durability, bucket policies, ACLs, S3 Object Lock, Lifecycle rules, S3 Intelligent-Tiering) vs Azure Blob Storage (Block blobs for files, Append blobs for logging, Page blobs for VHD disks, hierarchical namespace for Azure Data Lake Storage Gen2 analytics).
    🔍YT🔍G
  7. ☆
    Block Storage: AWS 'EBS' ↔ Azure 'Azure Managed Disks'
    AWS EBS (Elastic Block Store: gp3 baseline 3000 IOPS/125MBps, io2 Block Express up to 256k IOPS/4000MBps) vs Azure Managed Disks (Standard HDD, Standard SSD, Premium SSD v2, and Ultra Disk up to 160k IOPS for mission-critical databases; supports shared disks for clustering).
    🔍YT🔍G
  8. ☆
    File Storage: AWS 'EFS / FSx' ↔ Azure 'Azure Files'
    AWS EFS (Elastic File System, elastic POSIX NFSv4 shared across thousands of EC2 instances) & FSx (specialized for Lustre, Windows File Server, NetApp ONTAP) vs Azure Files (managed SMB 3.0 and NFSv4.1 shares, Azure File Sync for caching cloud files on on-premises Windows servers).
    🔍YT🔍G
  9. ☆
    Archive: AWS 'S3 Glacier' ↔ Azure 'Azure Archive Storage'
    AWS S3 Glacier Flexible & Deep Archive (retrieval times from minutes in expedited to 12 hours in deep archive; lowest cost long-term cold storage) vs Azure Archive Storage (offline blob tier with rehydration priority options: High priority 1-hour vs Standard 15-hour rehydration).
    🔍YT🔍G
  10. ☆
    Managed SQL DB: AWS 'RDS / Aurora' ↔ Azure 'Azure SQL / Cosmos DB SQL'
    AWS RDS (managed Postgres, MySQL, MariaDB, Oracle, SQL Server) & Aurora (cloud-native engine with decoupled storage, 6 copies across 3 AZs, 15 read replicas) vs Azure SQL Database (Hyperscale architecture with decoupled storage up to 100TB) & Azure Database for PostgreSQL Flexible Server.
    🔍YT🔍G
  11. ☆
    NoSQL: AWS 'DynamoDB' ↔ Azure 'Cosmos DB'
    AWS DynamoDB (fully managed distributed key-value/document store, single-digit ms latency, partition/sort key design, Global Tables for active-active multi-region) vs Azure Cosmos DB (turnkey multi-region multi-master, 5 well-defined consistency levels, SLA guarantees for latency and throughput).
    🔍YT🔍G
  12. ☆
    Cache: AWS 'ElastiCache' ↔ Azure 'Azure Cache for Redis'
    AWS ElastiCache (managed Redis OSS / Valkey and Memcached, cluster mode enabled with automated failover and read replicas) vs Azure Cache for Redis (Basic/Standard/Premium tiers, Enterprise tier powered by Redis Enterprise with active-active geo-replication and Redis modules).
    🔍YT🔍G
  13. ☆
    Data Warehouse: AWS 'Redshift' ↔ Azure 'Azure Synapse Analytics'
    AWS Redshift (petabyte-scale columnar MPP data warehouse, RA3 nodes with decoupled compute and managed storage, Redshift Serverless) vs Azure Synapse Analytics (formerly SQL DW, dedicated SQL pools with MPP architecture, serverless on-demand queries, integrated Apache Spark).
    🔍YT🔍G
  14. ☆
    Virtual Network: AWS 'VPC' ↔ Azure 'VNet'
    AWS VPC (Virtual Private Cloud: CIDR blocks, public/private subnets, Internet Gateways, NAT Gateways, Route Tables, VPC Peering) vs Azure VNet (Virtual Network: VNet address spaces, subnets, Network Security Groups / NSGs, VNet Peering, Virtual WAN hub-and-spoke).
    🔍YT🔍G
  15. ☆
    L4 Load Balancer: AWS 'NLB' ↔ Azure 'Azure Load Balancer'
    AWS Network Load Balancer (NLB: Layer 4 high-throughput ultra-low latency, static Elastic IPs per AZ, preserves source IP, handles millions of TCP/UDP connections) vs Azure Load Balancer (Layer 4 ultra-low latency load balancer, Standard SKU with zone redundancy and outbound SNAT rules).
    🔍YT🔍G
  16. ☆
    L7 Load Balancer: AWS 'ALB' ↔ Azure 'Application Gateway'
    AWS Application Load Balancer (ALB: Layer 7 HTTP/HTTPS/gRPC routing, host/path/header rules, TLS termination, integrated Cognito authentication) vs Azure Application Gateway (Layer 7 ADC with integrated Web Application Firewall / WAF v2, URL-based routing, multi-site hosting, cookie affinity).
    🔍YT🔍G
  17. ☆
    API Gateway: AWS 'API Gateway' ↔ Azure 'Azure API Management'
    AWS API Gateway (managed REST, HTTP, and WebSocket APIs, API key management, usage plans, throttling, Lambda authorizers) vs Azure API Management (APIM: developer portal, policy engine via XML transforms, mock responses, multi-gateway deployment for hybrid on-premises).
    🔍YT🔍G
  18. ☆
    CDN: AWS 'CloudFront' ↔ Azure 'Azure CDN / Front Door'
    AWS CloudFront (global CDN edge network, TLS 1.3, origin shield, Lambda@Edge and CloudFront Functions for edge compute) vs Azure Front Door & Azure CDN (global Anycast L7 network combining CDN, global load balancing, SSL offload, and WAF at Microsoft's global network edge).
    🔍YT🔍G
  19. ☆
    DNS: AWS 'Route 53' ↔ Azure 'Azure DNS'
    AWS Route 53 (highly available global authoritative DNS, latency-based, weighted, geolocation, geoproximity, and failover routing with health checks) vs Azure DNS (hosted DNS zones) & Azure Traffic Manager (DNS-based global traffic routing across endpoints).
    🔍YT🔍G
  20. ☆
    Identity: AWS 'IAM' ↔ Azure 'Azure Entra ID (AAD)'
    AWS IAM (Identity and Access Management: users, user groups, assumable IAM roles, JSON identity and resource-based policies, Permission Boundaries) vs Azure Entra ID (formerly Azure Active Directory: cloud identity provider, OAuth2/OIDC, Conditional Access policies, Azure RBAC roles).
    🔍YT🔍G
  21. ☆
    Secrets: AWS 'Secrets Manager' ↔ Azure 'Key Vault'
    AWS Secrets Manager (secure storage, fine-grained IAM access, automated lifecycle rotation for RDS/Redshift passwords via Lambda) vs Azure Key Vault (FIPS 140-2 validated HSM-backed storage for cryptographic keys, secrets, and SSL/TLS certificates with auto-renewal).
    🔍YT🔍G
  22. ☆
    Monitoring / Metrics: AWS 'CloudWatch' ↔ Azure 'Azure Monitor'
    AWS CloudWatch (centralized operational telemetry: infrastructure metrics, custom metrics, high-resolution alarms, metric math, synthetic canaries) vs Azure Monitor (unified platform for collecting metrics, metric alerts, dynamic threshold anomaly detection, Workbooks).
    🔍YT🔍G
  23. ☆
    Logging: AWS 'CloudWatch Logs' ↔ Azure 'Log Analytics'
    AWS CloudWatch Logs (log groups, log streams, metric filters, CloudWatch Logs Insights with SQL-like syntax, subscription filters to Kinesis/OpenSearch) vs Azure Log Analytics (part of Azure Monitor, centralized log aggregation, powerful Kusto Query Language / KQL for analytics).
    🔍YT🔍G
  24. ☆
    Tracing: AWS 'X-Ray' ↔ Azure 'Application Insights'
    AWS X-Ray (distributed request tracing, X-Ray daemon, trace segment propagation, service map visualization, latency bottleneck analysis) vs Azure Application Insights (distributed tracing, live metrics stream, application map, smart detection for failure anomalies).
    🔍YT🔍G
  25. ☆
    Event Bus: AWS 'EventBridge' ↔ Azure 'Event Grid'
    AWS EventBridge (serverless event bus routing JSON events between AWS services, SaaS applications, and custom microservices with content filtering rules) vs Azure Event Grid (event-driven routing engine using CloudEvents standard, high-throughput reactive pub-sub delivery).
    🔍YT🔍G
  26. ☆
    Message Queue: AWS 'SQS' ↔ Azure 'Service Bus Queues'
    AWS SQS (Simple Queue Service: Standard queues with near-unlimited throughput and at-least-once delivery; FIFO queues with strictly ordered exactly-once processing) vs Azure Service Bus Queues (enterprise messaging queue with ordered sessions, dead-lettering, duplicate detection, transactions).
    🔍YT🔍G
  27. ☆
    Pub-Sub: AWS 'SNS' ↔ Azure 'Service Bus Topics'
    AWS SNS (Simple Notification Service: pub-sub topic fan-out pushing messages to thousands of SQS queues, HTTP webhooks, Lambda functions, mobile push, and SMS) vs Azure Service Bus Topics (pub-sub topics with multiple subscriptions, each with individual SQL filter rules and actions).
    🔍YT🔍G
  28. ☆
    Streaming: AWS 'Kinesis' ↔ Azure 'Event Hubs'
    AWS Kinesis Data Streams (real-time streaming ingestion partitioned into shards, 1MB/s write per shard, replayable retention up to 365 days, KCL consumer scaling) vs Azure Event Hubs (real-time event ingestion partitioned for horizontal scale, Event Hubs Capture to Blob/Data Lake).
    🔍YT🔍G
  29. ☆
    IaC: AWS 'CloudFormation / CDK' ↔ Azure 'ARM Templates / Bicep'
    AWS CloudFormation & AWS CDK (declarative JSON/YAML templates or imperative TypeScript/Python code synthesizing CloudFormation stacks with drift detection) vs Azure ARM Templates & Bicep (Azure Resource Manager declarative JSON or concise domain-specific Bicep language).
    🔍YT🔍G
  30. ☆
    Email: AWS 'SES' ↔ Azure 'Azure Communication Services'
    AWS SES (Simple Email Service: cost-effective high-deliverability platform for transactional and marketing emails with DKIM, SPF, and DMARC verification) vs Azure Communication Services (multi-channel communications platform providing Email, SMS, Voice, and Video SDKs).
    🔍YT🔍G

Identity primitives

4 concepts
What gets authenticated.
  1. ☆
    IAM Users / Groups / Roles (AWS)
    IAM Entities: Users: Long-term credentials (passwords, access keys) for individuals (anti-pattern in production). Groups: Collections of users sharing policies. Roles: Credential-less identities assumed dynamically by services, users, or external IdPs issuing short-lived STS tokens.
    🔍YT🔍G
  2. ☆
    Managed Identity (Azure) / IAM Role for EC2 (AWS)
    Workload Identity: AWS IAM Roles for EC2 / IRSA for EKS: Injects temporary, auto-rotating credentials via Instance Metadata Service (IMDSv2). Azure Managed Identity: System-assigned or User-assigned identities managed by Microsoft Entra ID. Completely eliminates hardcoded API keys and secrets.
    🔍YT🔍G
  3. ☆
    Federation (SAML / OIDC / SSO)
    Enterprise Federation: Authenticates corporate users via external Identity Providers (Okta, Azure AD, Ping) using SAML 2.0 or OIDC. Exchanging enterprise assertions for scoped cloud STS session tokens eliminates duplicate user stores and centralizes Multi-Factor Authentication (MFA).
    🔍YT🔍G
  4. ☆
    AWS Organizations / Azure Management Groups
    Multi-Account Governance: AWS Organizations: Hierarchical tree of Organizational Units (OUs) governed by Service Control Policies (SCPs). Azure Management Groups: Nested subscription hierarchy governed by Azure Policies. Segregates blast radius across Production, Staging, Security, and Shared Services accounts.
    🔍YT🔍G
2.2

Policies & Permissions

4 concepts
How access is granted.
  1. ☆
    AWS IAM Policy (JSON: Effect / Action / Resource)
    IAM Policy Evaluation Logic: Default Deny → Explicit Deny (evaluates first; immediately overrides any Allow) → Explicit Allow → Default Deny. Conditions allow granular attribute-based access control (ABAC) based on IP address, VPC endpoint source, MFA status, or resource tags.
    🔍YT🔍G
  2. ☆
    Azure RBAC built-in roles (Owner/Contributor/Reader)
    Azure Role-Based Access Control: Security principals (Users, Groups, Service Principals) assigned built-in or custom roles (Owner, Contributor, Reader) scoped at Management Group, Subscription, Resource Group, or individual Resource levels.
    🔍YT🔍G
  3. ☆
    Permission boundaries / Service Control Policies
    Policy Guardrails: AWS SCPs: Organization-level filters setting the maximum permissible permissions for member accounts; cannot be bypassed even by the account root user. Permission Boundaries: Delegated administration guardrail preventing developers from creating overly permissive roles.
    🔍YT🔍G
  4. ☆
    Secrets Manager / Key Vault
    Secrets Management: Centralized vaults (AWS Secrets Manager, Azure Key Vault) storing database credentials, OAuth tokens, and certificates. Features automated rotation via Lambda functions, KMS envelope encryption at rest, and audit logging for every secret retrieval.
    🔍YT🔍G

Virtual Machines

6 concepts
EC2 / Azure VMs.
  1. ☆
    Instance families (general / compute / memory / GPU)
    Instance Families: General Purpose (m/t, D-series): Balanced compute, memory, and network for web servers. Compute Optimized (c, F-series): High compute-to-memory ratio for CPU-bound batch jobs and microservices. Memory Optimized (r/x, E-series): In-memory caches and relational databases. Accelerated Computing (p/g, N-series): NVIDIA GPUs for ML training/inference.
    🔍YT🔍G
  2. ☆
    AMI / VM Image
    Golden Images: Pre-baked virtual machine snapshots (AMI, Azure VM Image) containing hardened OS, security agents, and static dependencies built via HashiCorp Packer. Accelerates autoscaling instance boot times from 15 minutes to under 60 seconds.
    🔍YT🔍G
  3. ☆
    On-Demand vs Reserved vs Spot
    Purchasing Models: On-Demand: Pay by the second, zero commitment, highest unit price. Savings Plans / Reserved Instances: Commit to 1-3 year baseline usage for up to 72% discount. Spot / Spot VMs: Bid on spare cloud capacity for up to 90% discount, subject to 2-minute termination notice upon cloud reclamation; ideal for stateless workers.
    🔍YT🔍G
  4. ☆
    Auto Scaling Groups (ASG) / VM Scale Sets
    Auto Scaling: AWS ASG / Azure VMSS: Automatically adjusts fleet size based on dynamic metric tracking (target CPU utilization, SQS queue depth per instance). Maintains target capacity across multiple Availability Zones with automated health-check replacement.
    🔍YT🔍G
  5. ☆
    User Data / Cloud-init
    Instance Bootstrapping: Cloud-init and User Data shell scripts executed once during initial instance provisioning. Fetches runtime configs from Parameter Store, mounts storage volumes, and registers instance with discovery registries.
    🔍YT🔍G
  6. ☆
    Elastic IP / Static Public IP
    Static Public IP: Elastic IP (AWS) / Public IP (Azure): Static IPv4 addresses allocated to accounts and associated with ENIs. Enables persistent external endpoints that survive instance stop/start cycles without DNS propagation delays.
    🔍YT🔍G

Containers

4 concepts
Docker + Kubernetes managed.
  1. ☆
    ECS / ACI — no Kubernetes
    AWS ECS vs Azure Container Instances: ECS: Opinionated, deeply AWS-integrated container orchestrator managing Docker tasks across EC2 or Fargate without Kubernetes complexity. ACI: Hypervisor-isolated serverless container execution for quick burst tasks without orchestrator overhead.
    🔍YT🔍G
  2. ☆
    EKS / AKS — managed Kubernetes
    Managed Kubernetes: AWS EKS / Azure AKS: Cloud vendor manages, scales, and patches the Kubernetes control plane (API server, etcd) across multiple AZs with high availability SLAs. Customer provisions and manages worker node pools.
    🔍YT🔍G
  3. ☆
    Fargate / Container Apps — serverless containers
    Serverless Containers: AWS Fargate / Azure Container Apps: Run containers without provisioning, configuring, or scaling virtual machine clusters. Pay strictly for allocated vCPU and memory per second; eliminates OS security patching and node maintenance.
    🔍YT🔍G
  4. ☆
    ECR / Azure Container Registry
    Private Container Registries: Managed OCI-compliant registries (ECR, ACR) storing container images. Integrates with CI/CD pipelines, IAM role-based image pull authentication, cross-region replication, and automated vulnerability scanning (Clair, Inspector).
    🔍YT🔍G
3.3

Serverless

4 concepts
Lambda / Azure Functions.
  1. ☆
    Lambda / Azure Functions — event-driven compute
    Event-Driven FaaS: Serverless execution model running stateless functions in response to HTTP requests, queue messages, or database mutations. Automatically scales from zero to tens of thousands of concurrent executions with sub-second billing.
    🔍YT🔍G
  2. ☆
    Cold starts — causes and mitigation
    Cold Start Optimization: Latency incurred when provisioning a new microVM container environment (initializing JVM/Python runtimes, loading packages). Mitigations: Provisioned Concurrency (pre-warming execution pools), lightweight compiled runtimes (Go/Rust), AWS SnapStart (microVM snapshot restoration).
    🔍YT🔍G
  3. ☆
    Execution limits (timeout, memory, concurrency)
    Execution Limits: AWS Lambda caps execution time at 15 minutes, ephemeral storage at 10GB, and memory from 128MB to 10,240MB (allocating proportional CPU power). Default concurrency limit of 1,000 per region requires quota increase requests for high-throughput spikes.
    🔍YT🔍G
  4. ☆
    Step Functions / Logic Apps — orchestration
    Stateful Workflow Orchestration: AWS Step Functions / Azure Logic Apps: Visual declarative state machine orchestrating serverless distributed workflows. Manages sequential branching, parallel tasks, error retries with exponential backoff, and asynchronous human approval callbacks.
    🔍YT🔍G

4.1

Object Storage (S3 / Azure Blob)

7 concepts
The backbone of cloud storage.
  1. ☆
    Buckets / Containers — namespace and naming
    Object Storage Architecture: Flat key-value namespace storing unstructured data (blobs) accessed via HTTP REST APIs. Objects identified by bucket name and key string; provides 99.999999999% (11 9s) durability by redundantly storing data across ≥3 facilities.
    🔍YT🔍G
  2. ☆
    Storage classes / access tiers
    Storage Tiers & FinOps: S3 Standard: $0.023/GB for frequent access. Intelligent-Tiering: Automatically shifts objects between frequent, infrequent, and archive tiers without retrieval fees. Glacier Flexible: $0.0036/GB (retrieval in minutes/hours). Glacier Deep Archive: $0.00099/GB (retrieval 12-48h, 90% cheaper than Standard).
    🔍YT🔍G
  3. ☆
    Versioning + object lock
    Versioning & Compliance: Retains past iterations of overwritten or deleted objects to recover from accidental deletes. Object Lock: Enforces WORM (Write Once, Read Many) retention policies in Compliance or Governance mode to prevent deletion even by the account root user.
    🔍YT🔍G
  4. ☆
    Encryption at rest (SSE-S3, SSE-KMS, CMK)
    Server-Side Encryption: SSE-S3: AES-256 with vendor-managed keys (zero extra cost). SSE-KMS: Customer-managed KMS keys enabling envelope encryption, key rotation, and CloudTrail access audits (subject to KMS per-request pricing). SSE-C: Customer-provided keys.
    🔍YT🔍G
  5. ☆

Security Controls

4 concepts
Network-level firewall.
  1. ☆
    Security Groups (AWS) — stateful, instance-level
    Security Groups: Stateful, instance-level virtual firewall attached to Elastic Network Interfaces (ENIs). Inbound allow rules automatically permit corresponding return outbound traffic regardless of outbound rules. Evaluated as a holistic set (no deny rules).

  3. ☆
    NSGs (Azure) — stateful, subnet or NIC
    Azure Network Security Groups: Stateful security filter applied to subnets or NICs with 5-tuple matching (source IP, source port, destination IP, destination port, protocol). Evaluates prioritized rules from 100 to 4096 with default deny inbound.

  4. ☆
    SG vs NACL key differences (AWS exam favourite)
    SG vs NACL Architectural Comparison: Security Groups: Stateful, attached to ENI/instance, allow-only rules, evaluates all rules, first line of defence. NACL: Stateless, attached to subnet, allows and denies, ordered rule processing, acts as secondary blast-radius guardrail.

    Q: What is AWS?A: Cloud platform: compute, storage, networking, DB, analytics, AI, IoT.

In senior interviews, frame AWS around the Global Infrastructure: Regions (isolated geographic areas), Availability Zones (physically separated datacenters connected via redundant sub-2ms low-latency dark fiber), and Edge Locations (PoPs for CloudFront CDN and Route 53 DNS).

  2. ☆
    Q: EC2 pricing models?A: On-Demand, Reserved (1/3yr), Spot, Dedicated Host.
    Four foundational EC2 pricing tiers: 1. On-Demand (pay by the second, zero upfront, maximum flexibility for spiky workloads). 2.     S3 storage class spectrum: S3 Standard (frequently accessed data, 99.99% availability, 11 9s durability). S3 Intelligent-Tiering (automatically moves objects between tiers based on access patterns without operational overhead or retrieval fees). S3 Standard-IA (infrequently accessed, cheaper storage, retrieval fee). S3 One Zone-IA (stored in single AZ, 20% cheaper, vulnerable to AZ loss). S3 Glacier Flexible (retrieval in minutes to hours). S3 Glacier Deep Archive (lowest cost at ~$0.00099/GB/mo, retrieval within 12 hours).

    Q: EBS vs EFS vs S3?A: EBS = single-instance block. EFS = multi-mount NFS. S3 = object storage, no mount.
    Architectural storage differences: EBS (Elastic Block Store) is raw block storage attached over the network to a single EC2 instance, behaving like a physical hard drive (ideal for databases requiring low-latency random IOPS). EFS (Elastic File System) is an elastic POSIX NFSv4 shared file system mounted concurrently across thousands of EC2 instances and containers. S3 (Simple Storage Service) is an object store accessed via REST HTTP APIs (GET/PUT), offering virtually unlimited capacity and 11 9s durability.

    An Amazon Machine Image (AMI) is a pre-configured immutable template required to launch an EC2 instance. It bundles: 1.   7. ☆
    Q: Security Group vs NACL?A: SG = stateful, instance, allow-only. NACL = stateless, subnet, allow+deny.

Network ACLs (NACLs) operate at the **subnet boundary**, are **stateless** (return traffic must be explicitly allowed), evaluate rules in numbered order, and support both **ALLOW and DENY rules** (ideal for blocking malicious CIDR IP ranges).

    An Elastic IP (EIP) is a static, persistent public IPv4 address allocated to your AWS account that can be rapidly remapped between EC2 instances or Network Interfaces in the same region to mask instance failures. Launch Template (specifies AMI, instance type, security groups, user-data). 2. Auto Scaling Group (defines min/max/desired capacity and multi-AZ subnets). 3. Metrics (time-series performance counters collected at 1-minute standard or 1-second high resolution). 2. Alarms (triggers SNS notifications or Auto Scaling actions when thresholds breach). 3.     🔍YT🔍G
  2. ☆
    Q: Types of IAM policies?A: Managed (AWS or customer) and inline.
    Types of IAM Policies: 1. AWS Managed Policies (created and maintained by AWS, e.g. AdministratorAccess). 2. Customer Managed Policies (standalone, versioned, reusable policies authored by you). 3. Inline Policies (embedded directly into a single user, group, or role; discouraged due to lack of reusability). 4. Resource-based Policies (attached directly to resources like S3 bucket policies or KMS key policies).
    🔍YT🔍G
  3. ☆
    Q: IAM Role vs IAM User?A: Role = assumable, no long-lived creds. User = person, has access keys.
    IAM User vs IAM Role: An IAM User represents a permanent identity (person or legacy app) with long-lived credentials (console password and permanent access key pairs; severe security risk if leaked). An IAM Role is an assumable identity that does NOT have permanent credentials; AWS STS (Security Token Service) issues short-lived, auto-rotating temporary credentials (valid 15m to 12h). Always use IAM Roles for EC2 instances, Lambda functions, and cross-account access.
    🔍YT🔍G
  4. ☆
    Q: How to encrypt data in S3?A: SSE-S3 (managed keys), SSE-KMS (KMS keys), SSE-C (client keys).
    Three S3 server-side encryption modes: 1. SSE-S3 (AES-256 encryption managed entirely by S3 with zero extra cost; keys rotate automatically). 2. SSE-KMS (AWS KMS keys provide audit trail via CloudTrail and granular key policies, but KMS API requests incur per-request billing and account rate limits). 3. SSE-C (Client-provided keys: customer manages the cryptographic key, S3 performs the encryption/decryption on the fly and never stores the key).
    🔍YT🔍G
  5. ☆
    Q: What is KMS?A: Key Management Service. Create/manage/audit encryption keys. Integrated with S3, EBS, RDS.
    AWS Key Management Service (KMS) is a managed FIPS 140-2 Level 2/3 cryptographic service for creating and controlling symmetric and asymmetric Customer Master Keys (CMKs). KMS uses Envelope Encryption: KMS encrypts a Data Encryption Key (DEK) with the master key; the plaintext DEK encrypts the actual data, and the encrypted DEK is stored alongside the ciphertext, preventing KMS performance bottlenecks.
    🔍YT🔍G
  6. ☆
    Q: MFA in AWS?A: Additional auth factor. Required for root, recommended for all. Virtual (TOTP) or hardware.
    Multi-Factor Authentication (MFA) requires a second authentication factor beyond username/password. Mandated for root accounts and privileged IAM users. Options: Virtual MFA (TOTP smartphone apps like Google Authenticator), Hardware TOTP tokens, or FIDO2/WebAuthn hardware security keys (e.g. YubiKey). Enforced via IAM policy condition `aws:MultiFactorAuthPresent: 'true'`.
    🔍YT🔍G
  7. ☆
    Q: Explicit Deny vs Allow precedence?A: Explicit Deny ALWAYS wins over Allow, regardless of other policies.
    Evaluation logic for IAM policies: 1. Default Deny: all requests are implicitly denied. 2. Explicit Allow: granted if an applicable policy explicitly allows the action. 3. **Explicit Deny ALWAYS wins**: If any policy (Identity-based, Resource-based, Permissions Boundary, or Organization Service Control Policy / SCP) contains an explicit `Effect: Deny`, the request is immediately rejected regardless of how many other policies grant `Allow`.
    🔍YT🔍G

Networking & Load Balancing Q&A

6 concepts
VPC, ELB, Route 53.
  1. ☆
    Q: Types of AWS load balancers?A: ALB (L7/HTTP), NLB (L4/TCP), GLB (L3/firewalls), Classic (legacy).
    Four generations of Elastic Load Balancing (ELB): 1. ALB (Application Load Balancer: Layer 7 HTTP/HTTPS/gRPC, host/path-based routing, websockets, TLS offloading). 2. NLB (Network Load Balancer: Layer 4 TCP/UDP/TLS, millions QPS, static IPs, sub-millisecond latency). 3. Gateway Load Balancer (GWLB: Layer 3/4 bump-in-the-wire for deploying 3rd party firewalls/IDS). 4. Classic Load Balancer (CLB: deprecated legacy generation).
    🔍YT🔍G
  2. ☆
    Q: Sticky sessions?A: Route user to same instance. Cookie-based. Disrupts perfect load distribution.
    Sticky Sessions (Session Affinity) bind a user's session to a specific backend EC2/target container using an application or duration-based cookie. Architectural trade-off: ensures local in-memory session data remains accessible, but severely degrades load balancing fairness, causes traffic hotspots, and leads to session loss during rolling deployments or instance terminations. Senior recommendation: keep services stateless and store sessions in Redis.
    🔍YT🔍G
  3. ☆
    Q: What is a NAT Gateway?A: Lets private subnet instances reach internet (outbound), not the reverse. Managed by AWS.
    A NAT Gateway allows EC2 instances in private subnets to initiate outbound connections to the internet (e.g. for OS security patches or third-party APIs) while preventing external inbound traffic from initiating connections to private instances. Managed by AWS, scales automatically up to 100 Gbps, deployed per-AZ for high availability. In contrast to legacy self-hosted NAT instances, requires zero maintenance.
    🔍YT🔍G
  4. ☆
    Q: VPC default AWS resources?A: Route Table, Network ACL, Security Group (automatically created).
    When you create a default VPC, AWS automatically provisions: 1. Default Route Table (with local route). 2. Default Network ACL (allowing all inbound and outbound traffic). 3. Default Security Group (allowing all inbound from itself and all outbound). 4. Internet Gateway (attached to default VPC). 5. Public subnets in each Availability Zone with public IPv4 auto-assign enabled.
    🔍YT🔍G
  5. ☆
    Q: Route 53 routing policies?A: Simple, Weighted, Latency, Failover, Geolocation, Multi-value.
    Amazon Route 53 DNS routing policies: 1. Simple (single resource, no health checks). 2. Weighted (percentage distribution for canary rollouts). 3. Latency (routes to the AWS region with lowest latency for the client). 4. Failover (active-passive disaster recovery via health checks). 5. Geolocation (routes by client country/state). 6. Geoproximity (routes based on geographic distance with bias values). 7. Multi-value Answer (DNS load balancing with up to 8 healthy records).
    🔍YT🔍G
  6. ☆
    Q: 5 reserved IPs per subnet?A: .0 network,.1 VPC router,.2 DNS,.3 future,.255 broadcast.
    AWS reserves 5 IP addresses in every subnet CIDR block (e.g. in a 10.0.0.0/24 subnet with 256 addresses, only 251 are usable): .0 (Network address). .1 (Reserved by AWS for VPC router). .2 (Reserved by AWS for DNS server). .3 (Reserved by AWS for future use). .255 (Network broadcast address; AWS does not support broadcast, but address is reserved).
    🔍YT🔍G
10.4

RDS & DynamoDB Q&A

7 concepts
Database services.
  1. ☆
    Q: RDS DB engines?A: MySQL, Postgres, MariaDB, Oracle, SQL Server, Aurora (MySQL/Postgres compatible).
    Amazon RDS supports six relational database engines: PostgreSQL, MySQL, MariaDB, Oracle Database, Microsoft SQL Server, and Amazon Aurora (custom cloud-optimized MySQL and PostgreSQL compatible engine). RDS handles OS patching, automated point-in-time recovery, automated backups, and storage autoscaling.
    🔍YT🔍G
  2. ☆
    Q: Multi-AZ RDS?A: Sync standby in another AZ, automatic failover ~60s. For DR — NOT for read scaling.
    RDS Multi-AZ creates a synchronous physical standby replica in a different Availability Zone within the same region. In the event of primary instance failure, host degradation, or AZ outage, RDS automatically triggers a DNS failover to the standby in ~60-120 seconds with ZERO data loss. Crucial distinction: Multi-AZ is strictly for **High Availability & Disaster Recovery**, NOT for read scaling (the standby cannot accept read traffic).
    🔍YT🔍G
  3. ☆
    Q: RDS Read Replica vs Multi-AZ?A: RR = async, read scale, possible lag. MAZ = sync, HA/failover.
    Multi-AZ vs Read Replicas: Multi-AZ is **synchronous replication**, strictly within the same region (or multi-region Aurora), automated failover, handles write/read DR, standby is non-queryable. Read Replicas use **asynchronous replication**, can be placed in same AZ, cross-AZ, or cross-region, accept read-only queries to scale read-heavy workloads, and do NOT have automatic failover without manual promotion.
    🔍YT🔍G
  4. ☆
    Q: RDS backup types?A: Automated backups (retention 0-35d) and manual snapshots (kept until deleted).
    RDS Backup mechanisms: 1. Automated Backups: daily full snapshot paired with transaction logs saved every 5 minutes to S3; allows Point-in-Time Recovery (PITR) to any second within retention window (1 to 35 days); deleted automatically when DB is deleted unless retained. 2. Manual Snapshots: user-initiated full snapshots stored in S3 that persist indefinitely until explicitly deleted by the user.
    🔍YT🔍G
  5. ☆
    Q: What is DynamoDB?A: Fully managed NoSQL key-value and document DB. Single-digit ms at any scale.
    Amazon DynamoDB is a fully managed, serverless, multi-region NoSQL key-value and document database delivering single-digit millisecond response times at any scale. Partitioning is determined by Partition Key (HASH), with optional Sort Key (RANGE). Features: DynamoDB Streams (CDC log of mutations), Global Tables (active-active multi-region replication in under 1 second), and DynamoDB Accelerator (DAX) in-memory microsecond cache.
    🔍YT🔍G
  6. ☆
    Q: What is ElastiCache?A: Managed Redis or Memcached. In-memory cache. Reduces DB load.
    Amazon ElastiCache provides managed in-memory caching to eliminate relational database bottlenecks and achieve sub-millisecond read latency. Supports Redis (data structures, Pub/Sub, persistence, clustering, multi-AZ failover) and Memcached (simple multi-threaded key-value store, no persistence). Best practices: implement Cache-Aside with TTLs to prevent stale data.
    🔍YT🔍G
  7. ☆
    Q: What is Redshift?A: Managed data warehouse. Columnar, MPP, petabyte-scale. OLAP not OLTP.
    Amazon Redshift is a fully managed petabyte-scale cloud data warehouse designed for OLAP (Online Analytical Processing) business intelligence. Utilizes columnar storage (compresses identical column data by up to 70%), Massive Parallel Processing (MPP) across leader and compute nodes, and Redshift Spectrum / Concurrency Scaling to query exabytes of unstructured data directly in S3 without loading.
    🔍YT🔍G

SQS / SNS / Lambda / Misc Q&A

10 concepts
Messaging, serverless, more.
  1. ☆
    Q: SQS queue types?A: Standard (at-least-once, near-unlimited TPS) and FIFO (exactly-once, 3k TPS).
    Amazon SQS queue types: 1. Standard Queues: near-unlimited throughput, at-least-once delivery (duplicates can occur), best-effort ordering (messages can arrive out of sequence). 2. FIFO Queues: strictly preserved First-In-First-Out ordering, exactly-once processing (message deduplication ID), throughput limited to 300 msg/sec (or 3,000 msg/sec with batching / high-throughput mode).
    🔍YT🔍G
  2. ☆
    Q: SQS max message size?A: 256 KB.
    Amazon SQS has a maximum native payload size of **256 KB** per message (text or JSON). To transmit messages larger than 256 KB (up to 2 GB), use the open-source **Amazon SQS Extended Client Library for Java/Python**: the client uploads the large payload to an S3 bucket and sends a pointer reference containing the S3 bucket and object key through the SQS message.
    🔍YT🔍G
  3. ☆
    Q: SNS vs SQS?A: SNS = pub-sub fan-out. SQS = point-to-point queue. Often combined (SNS → SQS).
    SNS vs SQS architectural distinction: Amazon SNS is a **push-based pub-sub messaging service** (publisher sends one message to a topic; SNS immediately fans out and pushes to thousands of subscribers simultaneously). Amazon SQS is a **pull-based message queue** (workers poll the queue, process messages, and delete them). Production pattern: SNS + SQS Fan-Out (publish to 1 SNS topic; fan out to 5 dedicated SQS queues for parallel microservice ingestion).
    🔍YT🔍G
  4. ☆
    Q: What is CloudFormation?A: Infrastructure as Code. JSON/YAML templates → AWS resources. Free service.
    AWS CloudFormation is Amazon's native Infrastructure as Code (IaC) service. You author declarative JSON or YAML templates describing your desired AWS resources; CloudFormation provisions and configures them as an atomic stack. Features include Change Sets (preview modifications before applying), Rollback Triggers (auto-rollback on CloudWatch alarms), and Drift Detection (identifies unmanaged manual console changes).
    🔍YT🔍G
  5. ☆
    Q: What is Lambda?A: Serverless compute. Event-triggered. Pay per 100ms. Max 15-min timeout.
    AWS Lambda is an event-driven serverless compute service. You upload code, and Lambda executes it on lightweight Firecracker microVMs in response to events (S3 uploads, DynamoDB streams, API Gateway calls). Key constraints: maximum execution timeout of 15 minutes, ephemeral `/tmp` storage up to 10 GB, execution memory from 128 MB to 10,240 MB (CPU scales proportionally with allocated memory).
    🔍YT🔍G
  6. ☆
    Q: What is Elastic Beanstalk?A: PaaS for web apps. Upload code → EB handles provisioning, LB, scaling, health.
    AWS Elastic Beanstalk is an easy-to-use Platform as a Service (PaaS) for deploying web applications and services. Developers upload their application code (Node.js, Python, Java, Docker), and Elastic Beanstalk handles provisioning, load balancing, auto-scaling, and health monitoring automatically, while retaining full customer control over underlying EC2 and VPC resources.
    🔍YT🔍G
  7. ☆
    Q: What is CloudFront?A: CDN. Edge caches content globally. Integrates with S3, ALB, custom origins.
    Amazon CloudFront is a global Content Delivery Network (CDN) service that accelerates delivery of static and dynamic web content across 600+ Points of Presence (PoPs). It terminates TLS connections close to the end user, caches assets at edge locations with Origin Shield, and integrates with AWS WAF for DDoS mitigation and Lambda@Edge / CloudFront Functions for low-latency header transformations.
    🔍YT🔍G
  8. ☆
    Q: How many S3 buckets per account?A: 100 by default. Increase via support request.
    By default, AWS accounts have a soft limit of **100 S3 buckets per account** (can be increased up to 1,000 buckets via a Service Quotas increase request). There is NO limit on the number of objects you can store in an individual S3 bucket, and individual objects can range from 0 bytes up to **5 Terabytes**.
    🔍YT🔍G
  9. ☆
    Q: Can you reduce EBS volume size?A: No — only increase. To shrink: snapshot → new smaller volume → copy data.
    Can you reduce the size of an EBS volume? **No.** EBS Elastic Volumes allow dynamically increasing volume size, changing volume type (e.g. gp2 to gp3), or increasing IOPS without downtime, but reducing volume size is physically unsupported by the file system. To shrink: provision a new smaller EBS volume, attach both to an EC2 instance, format the new volume, copy the file data, and detach the old volume.
    🔍YT🔍G
  10. ☆
    Q: What is Snowball?A: Physical data transfer appliance. Petabytes in/out of AWS when network is impractical.
    AWS Snow Family (Snowcone, Snowball Edge, Snowmobile) provides physical, ruggedized hardware appliances for petabyte-to-exabyte scale offline data migration into and out of AWS when transferring data over public internet networks is physically cost-prohibitive or would take months. Snowball Edge Storage Optimized provides up to 80 TB of usable storage with 40GbE network interfaces.
    🔍YT🔍G
