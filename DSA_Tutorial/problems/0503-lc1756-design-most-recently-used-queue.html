#1756 Design Most Recently Used Queue MediumLeetCode

📋 The problem

Design a queue where fetching the k-th item also moves it to the back (most recently used).

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

Design a queue-like data structure that moves the most recently used element to the end of the queue. Support fetch(k) which moves the $k$-th element (1-indexed) to the end and returns it.

Square Root Decomposition (or Fenwick Tree / Balanced BST): With $n = 2000$, a standard list pop(k-1) and append() takes $O(n)$ time. Using $\sqrt{N}$ Buckets: Divide the $n$ elements into $pprox \sqrt{N}$ small buckets of size $pprox \sqrt{N}$. To fetch the $k$-th element: 1. Locate which bucket contains $k$ in $O(\sqrt{N})$ time. 2. Pop element from that bucket and append to the last bucket. 3. If necessary, rebalance bucket sizes in $O(\sqrt{N})$ time.

🐢 Brute force vs optimal

Python's dynamic array list.pop(k-1) and append() is extremely optimized in C and passes within 50ms for $N = 2000$. For $N = 10^5$, $\sqrt{N}$ decomposition guarantees $O(\sqrt{N})$ per fetch.

💡 Key insight: $\sqrt{N}$ bucket decomposition or dynamic list slicing: fetch locates target in $O(\sqrt{N})$, extracts, and appends to rear.

✅ The solution

Reveal the commented solution (attempt it first!) 
class MRUQueue:
    def __init__(self, n: int):
        self.q = list(range(1, n + 1))

    def fetch(self, k: int) -> int:
        val = self.q.pop(k - 1)
        self.q.append(val)
        return val

Complexity

Time: $O(n)$ worst case, $O(\sqrt{n})$ with block decomposition.
Space: $O(n)$ — Queue storage.
