#1293 Shortest Path in a Grid with Obstacles Elimination HardLeetCode

 

Pattern: Graph Traversal Patterns (DFS & BFS) › Subpattern 9.11: Graph - BFS on State Space · Problem 326 of 699

📋 The problem

Shortest path from corner to corner of a grid when you may remove up to k obstacles (BFS over (cell, removals-left)).

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

You are given an m x n integer matrix grid where each cell is either 0 (empty) or 1 (obstacle). You can move up, down, left, or right. You can eliminate at most k obstacles. Return the minimum number of steps to walk from (0, 0) to (m - 1, n - 1), or -1 if no such walk exists.

Because each step has unit cost 1, the shortest path is solved with Breadth-First Search (BFS). However, this is not a standard 2D grid BFS—it is a 3D State Space BFS where a state is defined by (row, col, remaining_eliminations)!

🐢 Brute force vs optimal

DFS explores all exponential branching paths. In BFS, each layer represents 1 additional step. If we track visited states as (r, c, k_remaining), the first time we pop destination (m - 1, n - 1), its step count is guaranteed to be globally minimal!

💡 Key insight:
  1. Manhattan Distance Shortcut: The shortest possible path from (0,0) to (m-1, n-1) without any obstacles is m + n - 2. If k >= m + n - 2, we have enough eliminations to blast straight through every single obstacle along the Manhattan path! Return m + n - 2 immediately in O(1)!
  2. State Pruning: If we have already visited cell (r, c) with rem_k eliminations remaining, visiting it later with ≤ rem_k eliminations is strictly worse and can be pruned! Maintain visited[r][c] = max_k_remaining_seen.

🪜 The approach, step by step

  1. Let m = len(grid), n = len(grid[0]).
  2. If k >= m + n - 2, return m + n - 2.
  3. Initialize queue: q = deque([(0, 0, k, 0)]) representing (r, c, k_rem, steps).
  4. Initialize visited = {(0, 0): k} mapping (r, c) → max_k_remaining.
  5. While q:
    • Pop (r, c, k_rem, steps).
    • If r == m - 1 and c == n - 1, return steps!
    • For each neighbor (nr, nc):
      • If inside grid:
        • Calculate new eliminations: next_k = k_rem - grid[nr][nc].
        • If next_k >= 0 and next_k > visited.get((nr, nc), -1):
          • Record visited[(nr, nc)] = next_k.
          • Push (nr, nc, next_k, steps + 1) into q.
  6. Return -1.

✅ The solution

from collections import deque

def shortestPath(grid: list[list[int]], k: int) -> int:
    """
    Finds shortest path in grid with at most k obstacle eliminations using 3D State BFS.
    """
    m, n = len(grid)
    if m == 1 and n == 1:
        return 0
        
    # Manhattan shortcut: if k is large enough, walk direct shortest path
    if k >= m + n - 2:
        return m + n - 2
        
    # Queue stores: (row, col, k_remaining, steps)
    q = deque([(0, 0, k, 0)])
    # visited maps (row, col) -> max k_remaining seen so far
    visited = {(0, 0): k}
    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]
    
    while q:
        r, c, k_rem, steps = q.popleft()
        
        if r == m - 1 and c == n - 1:
            return steps
            
        for dr, dc in dirs:
            nr, nc = r + dr, c + dc
            if 0 <= nr < m and 0 <= nc < n:
                next_k = k_rem - grid[nr][nc]
                if next_k >= 0 and next_k > visited.get((nr, nc), -1):
                    visited[(nr, nc)] = next_k
                    q.append((nr, nc, next_k, steps + 1))
                    
    return -1

⚡ Complexity analysis

  • Time Complexity: O(M × N × K). Each state (r, c, k_remaining) is enqueued at most once. Transitions take O(1) across 4 directions.
  • Space Complexity: O(M × N × K) for the visited dictionary and BFS queue.

🚨 Edge cases to watch out for

  • m = 1, n = 1: Returns 0 immediately.
  • grid[0][0] == 1: If start cell has obstacle, handled by decrementing initial k.
