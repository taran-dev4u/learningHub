📋 The problem

Find a path from corner to corner minimizing the maximum height difference along it (binary search + BFS, or Dijkstra on effort).

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

You are given a 2D grid heights of size rows x cols. A path's effort is the maximum absolute difference in heights between two consecutive cells of the route. You need to find the minimum effort required to travel from (0, 0) to (rows - 1, cols - 1).

Notice the bottleneck property: we want to find a route whose peak edge difference is minimized. This can be viewed through two lens:

  1. Modified Dijkstra's Algorithm: Treat each cell as a graph vertex. The distance to a cell is the maximum effort seen along the path to it. A min-heap always expands the path with the smallest peak effort.
  2. Binary Search on Answer + BFS: Since effort is bounded in [0, 10^6], binary search the effort threshold and run a simple BFS/DFS checking if (rows-1, cols-1) is reachable using only step differences ≤ mid.

🐢 Brute force vs optimal

Exploring all simple paths with DFS/backtracking takes O(4^(m × n)) exponential time. Modified Dijkstra operates in O((m × n) log(m × n)), which runs comfortably within 100ms.

💡 Key insight: In standard Dijkstra, new path cost is dist + edge_weight. In Minimum Effort, new path cost is max(effort_so_far, abs(heights[r][c] - heights[nr][nc])). The min-heap guarantees that the first time we pop destination (rows - 1, cols - 1), its recorded effort is globally minimal!

🪜 The approach, step by step

  1. Let m = len(heights) and n = len(heights[0]).
  2. Initialize distance table dist = [[float('inf')] * n for _ in range(m)]. Set dist[0][0] = 0.
  3. Min-heap pq = [(0, 0, 0)] containing tuples (effort, r, c).
  4. While pq is not empty:
    • Pop (effort, r, c).
    • If (r, c) == (m - 1, n - 1), return effort immediately!
    • If effort > dist[r][c], continue (stale entry).
    • For each of the 4 cardinal neighbors (nr, nc):
      • Calculate step effort: next_effort = max(effort, abs(heights[r][c] - heights[nr][nc])).
      • If next_effort < dist[nr][nc]: update dist[nr][nc] = next_effort and push (next_effort, nr, nc) into pq.

✅ The solution

Python 3 — Modified Dijkstra (Min-Heap) 
import heapq

def minimumEffortPath(heights: list[list[int]]) -> int:
    """
    Finds path from (0,0) to bottom-right cell with minimum peak consecutive elevation difference.
    """
    m, n = len(heights), len(heights[0])
    # dist[r][c] stores minimum effort to reach cell (r, c)
    dist = [[float('inf')] * n for _ in range(m)]
    dist[0][0] = 0
    
    # Priority queue stores (effort, row, col)
    pq = [(0, 0, 0)]
    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]
    
    while pq:
        effort, r, c = heapq.heappop(pq)
        
        # Reached destination: first pop is guaranteed minimum
        if r == m - 1 and c == n - 1:
            return effort
            
        if effort > dist[r][c]:
            continue
            
        for dr, dc in dirs:
            nr, nc = r + dr, c + dc
            if 0 <= nr < m and 0 <= nc < n:
                step_effort = abs(heights[r][c] - heights[nr][nc])
                new_effort = max(effort, step_effort)
                
                if new_effort < dist[nr][nc]:
                    dist[nr][nc] = new_effort
                    heapq.heappush(pq, (new_effort, nr, nc))
                    
    return 0

⚡ Complexity analysis

  • Time Complexity: O((m × n) log(m × n)). There are V = m × n cells and at most E = 4 × m × n edges. Heap operations take O(log(m × n)).
  • Space Complexity: O(m × n) to store the dist matrix and priority queue.

🚨 Edge cases to watch out for

  • 1×1 grid: Start cell is the destination; while loop immediately hits r == 0 and c == 0 and returns 0 effort.
  • Flat grid (all heights equal): Effort is 0 across all transitions.
