📋 The problem

Design a stack that supports push, pop, top, and retrieving the minimum element, all in O(1).

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

Design a stack that supports push, pop, top, and retrieving the minimum element in $O(1)$ time.

A standard stack gives $O(1)$ access only to the top element. To retrieve the global minimum in $O(1)$, we must maintain the minimum value for every state of the stack! When we push value $x$, the minimum of the stack at this height is: $$ ext{curr\_min} = \min(x, \; ext{previous\_min})$$ We can either: 1. Store a pair (val, min_so_far) on a single stack. 2. Maintain a secondary min_stack that stores the running minimum.

🐢 Brute force vs optimal

Scanning the stack for the minimum on getMin() takes $O(n)$ time. Tracking running minimums at each level guarantees $O(1)$ for all operations.

💡 Key insight: Push pairs (val, min(val, stack[-1][1])). The second value always gives the minimum element in the stack up to that height in $O(1)$ time!

✅ The solution

Reveal the commented solution (attempt it first!) 
class MinStack:
    def __init__(self):
        # Stack stores tuples: (value, current_min)
        self.stack = []

    def push(self, val: int) -> None:
        if not self.stack:
            self.stack.append((val, val))
        else:
            curr_min = min(val, self.stack[-1][1])
            self.stack.append((val, curr_min))

    def pop(self) -> None:
        self.stack.pop()

    def top(self) -> int:
        return self.stack[-1][0]

    def getMin(self) -> int:
        return self.stack[-1][1]

Complexity

Time: $O(1)$ for push, pop, top, and getMin.
Space: $O(n)$ — Stack storage holding element pairs.
