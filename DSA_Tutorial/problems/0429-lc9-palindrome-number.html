#9 Palindrome Number EasyLeetCode

 

Pattern: String Manipulation Patterns › Subpattern 13.1: Palindrome Check / Two Pointers / Reverse · Problem 429 of 699

📋 The problem

Determine whether an integer reads the same forwards and backwards, without converting it to a string.

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

Given an integer x, return true if x is a palindrome, and false otherwise.

Negative numbers cannot be palindromes (e.g. -121 reversed is 121-). Also, any positive number ending in 0 (except 0 itself) cannot be a palindrome (leading digit cannot be 0).

The O(1) Space Half-Reversal Trick: Instead of converting to string (which takes $O(\log_{10} x)$ memory) or reversing the entire integer (which risks 32-bit overflow), reverse only the second half of the number! When x <= reversed_num, we have reached the midpoint: - For even digits (e.g. 1221): x == reversed_num (12 == 12). - For odd digits (e.g. 12321): x == reversed_num // 10 (12 == 123 // 10).

🐢 Brute force vs optimal

String conversion uses heap allocation and $O(n)$ space. Half-number arithmetic reversal runs in $O(\log_{10} n)$ time with zero string allocations and zero overflow risk.

💡 Key insight: Reverse digits from the right into rev = rev * 10 + x % 10; x //= 10 until x <= rev. Check x == rev or x == rev // 10.

✅ The solution

Reveal the commented solution (attempt it first!) 
def isPalindrome(x: int) -> bool:
    # Negative numbers and non-zero multiples of 10 cannot be palindromes
    if x < 0 or (x % 10 == 0 and x != 0):
        return False
        
    rev = 0
    while x > rev:
        rev = rev * 10 + (x % 10)
        x //= 10
        
    # When length is odd, discard middle digit via rev // 10
    return x == rev or x == rev // 10

Complexity

Time: $O(\log_{10} n)$ — Divide by 10 at each step; takes at most $\approx 5$ iterations for 32-bit int.
Space: $O(1)$ — Only arithmetic scalar variables.
