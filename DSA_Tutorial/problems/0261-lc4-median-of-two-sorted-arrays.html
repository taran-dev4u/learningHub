📋 The problem

Given two sorted arrays, return the median of all their elements combined, in O(log(m+n)) time.

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

Given two sorted arrays nums1 and nums2 of size m and n respectively, return the median of the two sorted arrays. The overall run time complexity should be O(log(m + n)).

🐢 Brute force first

Merge both arrays using two pointers into an array of size m + n, then pick the middle element. Time: O(m + n), Space: O(m + n). Violates the logarithmic constraint.

💡 Key insight: Partition both arrays simultaneously! A median partitions a combined set of m + n elements into two equal halves (left half and right half) where every element in the left half <= every element in the right half! If we take i elements from nums1, we must take j = (m + n + 1) // 2 - i elements from nums2. Binary search i on the shorter array!

🪜 The approach, step by step

  1. Ensure nums1 is the shorter array (if not, swap nums1, nums2). This guarantees O(log(min(m, n))).
  2. Set left = 0, right = m (number of elements to take from nums1 into left partition).
  3. While left <= right:
  4. i = left + (right - left) // 2.
  5. j = (m + n + 1) // 2 - i.
  6. Border values:
    • maxLeft1 = nums1[i-1] if i > 0 else -inf
    • minRight1 = nums1[i] if i < m else +inf
    • maxLeft2 = nums2[j-1] if j > 0 else -inf
    • minRight2 = nums2[j] if j < n else +inf
  7. Check partition validity:
    • If maxLeft1 <= minRight2 and maxLeft2 <= minRight1: Perfect partition!
      • If (m + n) % 2 == 1: return max(maxLeft1, maxLeft2).
      • Else: return (max(maxLeft1, maxLeft2) + min(minRight1, minRight2)) / 2.0.
    • If maxLeft1 > minRight2: too many elements from nums1, shift left: right = i - 1.
    • Else: too few elements from nums1, shift right: left = i + 1.

✅ The solution

def findMedianSortedArrays(nums1, nums2):
    # Ensure nums1 is shorter to guarantee log(min(m, n))
    if len(nums1) > len(nums2):
        nums1, nums2 = nums2, nums1
        
    m, n = len(nums1), len(nums2)
    left, right = 0, m
    total_left = (m + n + 1) // 2
    
    while left <= right:
        i = left + (right - left) // 2
        j = total_left - i
        
        max_left1 = float('-inf') if i == 0 else nums1[i - 1]
        min_right1 = float('inf') if i == m else nums1[i]
        
        max_left2 = float('-inf') if j == 0 else nums2[j - 1]
        min_right2 = float('inf') if j == n else nums2[j]
        
        if max_left1 <= min_right2 and max_left2 <= min_right1:
            # Correct partition found
            if (m + n) % 2 == 1:
                return float(max(max_left1, max_left2))
            else:
                return (max(max_left1, max_left2) + min(min_right1, min_right2)) / 2.0
        elif max_left1 > min_right2:
            right = i - 1
        else:
            left = i + 1
            
    return 0.0

⏱️ Complexity

Time O(log(min(m, n))) — Binary search on the shorter array. Space O(1).

⚠️ Edge cases

  • One array is empty: handled smoothly by -inf and +inf sentinels.
  • Arrays of different lengths (e.g. m=1, n=1000).
  • Combined length odd vs even.
