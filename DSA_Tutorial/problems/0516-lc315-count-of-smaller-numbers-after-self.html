📋 The problem

For each element, count how many elements to its right are smaller than it.

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

Given an integer array nums, return an integer array counts where counts[i] is the number of smaller elements to the right of nums[i].

Scan nums in reverse order (from right to left)! When we are at index $i$: Every element to the right of index $i$ has already been processed and inserted into our tracking data structure! We need to count how many inserted elements are strictly less than $nums[i]$.

Fenwick Tree (BIT) with Coordinate Compression: 1. Coordinate compression maps arbitrary integer values to ranked indices $1 \dots M$ ($M \le N$). 2. For each number $x$ from right to left: - Query prefix sum in Fenwick tree up to rank $rank(x) - 1$: count = query(rank - 1) - Insert $x$ into Fenwick tree: add(rank, 1)

🐢 Brute force vs optimal

Comparing every pair takes $O(N^2)$ time. Fenwick tree with coordinate compression evaluates in $O(N \log N)$ time and $O(N)$ space.

💡 Key insight: Traverse right-to-left. Query Fenwick tree for query(rank - 1), then add(rank, 1). Executes in $O(N \log N)$ time!

✅ The solution

def countSmaller(nums: list[int]) -> list[int]:
    # Coordinate compression
    ranks = {val: i + 1 for i, val in enumerate(sorted(set(nums)))}
    m = len(ranks)
    bit = [0] * (m + 1)
    
    def add(i, delta):
        while i <= m:
            bit[i] += delta
            i += i & (-i)
            
    def query(i):
        s = 0
        while i > 0:
            s += bit[i]
            i -= i & (-i)
        return s
        
    res = []
    # Traverse from right to left
    for x in reversed(nums):
        r = ranks[x]
        res.append(query(r - 1))
        add(r, 1)
        
    return res[::-1]

Complexity

Time: $O(N \log N)$ — Sorting for coordinate compression + $N$ Fenwick queries.
Space: $O(N)$ — Fenwick tree array and ranks map.
