📋 The problem

Design a class that accepts streaming numbers and always reports the k-th largest so far.

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

You need to continuously find the kth largest element in a stream of numbers as new values arrive. If we keep only the k largest numbers in a min-heap, the smallest of these k numbers is at the root — which is exactly the kth largest element.

🐢 Brute force first

Append each incoming value to a list, sort the list descending, and return index k - 1 on each add() call → O(n log n) per addition.

💡 Key insight: a min-heap of fixed size k. The heap root heap[0] is always the kth largest element. On adding val: if heap size < k, push it; else if val > heap[0], push and pop via heappushpop().

🪜 The approach, step by step

  1. Store k and convert the initial list into a heap using heapify.
  2. While heap size exceeds k, pop the excess smaller elements.
  3. In add(val): if len(heap) < k, push val; if len(heap) == k and val > heap[0], use heapreplace(heap, val).
  4. Return heap[0].

🎞️ Visual dry run — k = 3, nums = [4, 5, 8, 2], add(3), add(5)

Init [4, 5, 8, 2] → heapify → pop min 2 → heap of size 3: [4, 5, 8]
add(3): 3 < heap[0] (4) → 3 cannot enter top 3 → return 4
add(5): 5 > heap[0] (4) → replace 4 with 5 → heap: [5, 5, 8] → return 5

✅ The solution

Reveal the commented solution (attempt it first!) 
import heapq

class KthLargest:
    def __init__(self, k: int, nums: list[int]):
        self.k = k
        self.heap = nums
        heapq.heapify(self.heap)
        # Trim heap down to size k
        while len(self.heap) > k:
            heapq.heappop(self.heap)

    def add(self, val: int) -> int:
        if len(self.heap) < self.k:
            heapq.heappush(self.heap, val)
        elif val > self.heap[0]:
            heapq.heapreplace(self.heap, val)   # pop root and push val in O(log k)
        return self.heap[0]

⏱️ Complexity

Time O(log k) per add() call; O(n log k) for initialization. Space O(k) for maintaining the heap.

⚠️ Edge cases

  • Initial nums length is less than k (e.g. k=3, nums=[1, 2]): heap size grows to k upon subsequent add() calls.
  • Negative values: integer comparisons handle negatives correctly.

🐛 Common mistakes

  • Using a max-heap: you would need to pop and restore k-1 elements on every query, making each add() O(k log n).
