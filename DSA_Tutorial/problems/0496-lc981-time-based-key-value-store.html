📋 The problem

Design a key-value store where set stamps a timestamp and get(key, t) returns the value set at the latest time ≤ t.

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

Design a time-based key-value data structure that can store multiple values for the same key at different time stamps and retrieve the key's value at a certain timestamp.

Notice the critical constraint: All timestamps for set are strictly increasing! Therefore, for each key, the list of (timestamp, value) pairs is already naturally sorted by timestamp!

To get(key, timestamp): 1. Lookup the sorted list for key in a hash map: history = data[key]. 2. Use Binary Search (bisect_right) to find the largest timestamp $\le ext{target timestamp}$ in $O(\log N)$ time!

🐢 Brute force vs optimal

Linear scan of history takes $O(N)$ per query. Binary search evaluates in $O(\log N)$ time.

💡 Key insight: Timestamps are monotonically increasing: store pairs (timestamp, value) in a list per key. Query with bisect_right in $O(\log N)$!

✅ The solution

Reveal the commented solution (attempt it first!) 
from collections import defaultdict
import bisect

class TimeMap:
    def __init__(self):
        # key -> list of (timestamp, value)
        self.data = defaultdict(list)

    def set(self, key: str, value: str, timestamp: int) -> None:
        self.data[key].append((timestamp, value))

    def get(self, key: str, timestamp: int) -> str:
        if key not in self.data:
            return ""
        history = self.data[key]
        # Binary search for rightmost timestamp <= query timestamp
        idx = bisect.bisect_right(history, (timestamp, chr(127))) - 1
        if idx >= 0:
            return history[idx][1]
        return ""

Complexity

Time: set: $O(1)$ append. get: $O(\log N)$ binary search.
Space: $O(Total \; Sets)$ — List storage per key.
