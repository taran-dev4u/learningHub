#1095 Find in Mountain Array HardLeetCode

📋 The problem

Find a target's index in a mountain array (increases then decreases) with a limited number of reads (three binary searches).

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

Given a mountain array mountainArr, return the minimum index such that mountainArr.get(index) == target. If such an index does not exist, return -1. Access to the array is only through an interface MountainArray.get(k) and MountainArray.length(). Submissions making more than 100 calls to get will be judged Wrong Answer.

🐢 Brute force first

Linear scan calling get(i) for all i will exceed 100 calls for arrays up to 10,000 elements.

💡 Key insight: A mountain array consists of two monotonic halves split by the peak: an ascending left half and a descending right half. Execute a 3-phase binary search: 1. Find peak index using binary search (at most ~14 calls). 2. Binary search for target in the strictly increasing left half [0, peak] (~14 calls). 3. If not found in left half, binary search in strictly decreasing right half [peak + 1, n - 1] (~14 calls). Total calls: ~42 << 100 limit!

🪜 The approach, step by step

  1. Phase 1: Find Peak: left = 0, right = n - 1. While left < right, if get(mid) < get(mid + 1): left = mid + 1, else right = mid. peak = left.
  2. Phase 2: Search Left Half (Ascending): left = 0, right = peak. Standard ascending binary search. If found, return index immediately (satisfies minimum index requirement).
  3. Phase 3: Search Right Half (Descending): left = peak + 1, right = n - 1. Note the comparison logic is inverted since values decrease as index increases.
  4. If neither finds target, return -1.

🎞️ Visual dry run — array = [1, 2, 3, 4, 5, 3, 1], target = 3

1. Find peak: peak is index 4 (val = 5).
2. Search left [0, 4] for target 3:
   mid = 2, get(2) = 3 == 3 → Found at index 2!
   Return 2 immediately without needing to search the right half. ✓

✅ The solution

def findInMountainArray(target, mountain_arr):
    n = mountain_arr.length()
    
    # Phase 1: Find peak index
    left, right = 0, n - 1
    while left < right:
        mid = left + (right - left) // 2
        if mountain_arr.get(mid) < mountain_arr.get(mid + 1):
            left = mid + 1
        else:
            right = mid
    peak = left
    
    # Phase 2: Binary search on ascending left slope [0, peak]
    left, right = 0, peak
    while left <= right:
        mid = left + (right - left) // 2
        val = mountain_arr.get(mid)
        if val == target:
            return mid
        elif val < target:
            left = mid + 1
        else:
            right = mid - 1
            
    # Phase 3: Binary search on descending right slope [peak + 1, n - 1]
    left, right = peak + 1, n - 1
    while left <= right:
        mid = left + (right - left) // 2
        val = mountain_arr.get(mid)
        if val == target:
            return mid
        elif val < target:
            # Decreasing slope: smaller values are to the right
            right = mid - 1
        else:
            left = mid + 1
            
    return -1

⏱️ Complexity

Time O(log n) — 3 binary searches each taking O(log n). Total API calls <= 3 * log2(10000) ≈ 42 calls. Space O(1).

⚠️ Edge cases

  • Target exists on both slopes: algorithm returns left index first because left slope is searched first.
  • Target is at the peak: found during left slope search.
  • Target not in array: returns -1 after exhaustive search.
