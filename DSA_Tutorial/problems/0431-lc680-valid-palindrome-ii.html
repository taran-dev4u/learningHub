📋 The problem

Decide whether a string can become a palindrome after deleting at most one character.

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

Given a string s, return true if the s can be palindrome after deleting at most one character from it.

Run standard two pointers from ends: l = 0, r = len(s) - 1. The moment we encounter a mismatch s[l] != s[r], we have reached the fork in the road! We are allowed exactly one deletion: 1. Delete character at $l$: check if substring $s[l+1 \dots r]$ is a palindrome. 2. Delete character at $r$: check if substring $s[l \dots r-1]$ is a palindrome. If either subproblem is a valid palindrome, return True; otherwise return False!

🐢 Brute force vs optimal

Trying all $n$ single deletions takes $O(n^2)$. Checking the first mismatch with two substring checks takes $O(n)$ time and $O(1)$ space.

💡 Key insight: At the first mismatch s[l] != s[r], test if s[l+1:r+1] or s[l:r] is palindromic. Greedily terminates in $O(n)$ time.

✅ The solution

Reveal the commented solution (attempt it first!) 
def validPalindrome(s: str) -> bool:
    def is_pali_range(i: int, j: int) -> bool:
        while i < j:
            if s[i] != s[j]:
                return False
            i += 1
            j -= 1
        return True
        
    l, r = 0, len(s) - 1
    while l < r:
        if s[l] != s[r]:
            return is_pali_range(l + 1, r) or is_pali_range(l, r - 1)
        l += 1
        r -= 1
        
    return True

Complexity

Time: $O(n)$ — At most two linear scans.
Space: $O(1)$ — Constant pointers.
