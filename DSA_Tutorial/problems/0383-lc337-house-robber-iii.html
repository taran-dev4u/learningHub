📋 The problem

Houses form a binary tree; robbing two directly linked houses trips the alarm — return the maximum loot.

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

The thief has found himself in a new neighborhood where houses form a binary tree. If two directly-linked houses are broken into on the same night, the alarm automatically alerts the police. Find the maximum amount of money the thief can rob without alerting the police.

For any subtree rooted at node, the thief has two mutual exclusive choices: 1. Rob this node: We gain node.val, but we cannot rob either of its immediate children. We must take the optimal "not robbed" values from both children. 2. Do not rob this node: We are free to either rob or not rob each child independently (taking $\max(\text{rob}, \text{not\_rob})$ for each).

🐢 Brute force vs optimal

A naive recursive approach checking grandparents causes exponential recomputations. Instead, post-order DFS returns a tuple (rob_node, not_rob_node) for each subtree in a single bottom-up pass in $O(n)$ time.

💡 Key insight: Post-order traversal returns (rob, not_rob):
rob = node.val + left_not_rob + right_not_rob
not_rob = max(left_rob, left_not_rob) + max(right_rob, right_not_rob).

✅ The solution

Reveal the commented solution (attempt it first!) 
def rob(root) -> int:
    def dfs(node):
        if not node:
            return (0, 0) # (rob_this, skip_this)
            
        left_rob, left_skip = dfs(node.left)
        right_rob, right_skip = dfs(node.right)
        
        # If we rob this node, we cannot rob left or right children
        rob_curr = node.val + left_skip + right_skip
        
        # If we skip this node, children can either be robbed or skipped
        skip_curr = max(left_rob, left_skip) + max(right_rob, right_skip)
        
        return (rob_curr, skip_curr)
        
    return max(dfs(root))

Complexity

Time: $O(n)$ — Every tree node is visited exactly once.
Space: $O(h)$ — Call stack height where $h$ is tree height ($O(\log n)$ balanced, $O(n)$ skewed).
