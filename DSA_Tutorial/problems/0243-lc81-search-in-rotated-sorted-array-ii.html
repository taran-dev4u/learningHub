📋 The problem

Search a target in a rotated sorted array that may contain duplicates; return whether it exists.

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

Given the array nums after rotation, and an integer target, return true if target is in nums, or false if it is not. This problem differs from LC 33 because nums may contain duplicate elements.

🐢 Brute force first

Linear scan O(n). Because duplicates can mask which half is sorted, the worst-case for binary search is actually O(n) too (e.g. [1, 1, 1, 1, 2, 1, 1]).

💡 Key insight: When duplicates exist, nums[left] == nums[mid] == nums[right] can happen! When this occurs, we cannot determine whether the left or right half is sorted. The remedy is simple: shrink both boundaries left += 1 and right -= 1, shedding the ambiguity safely without losing a target that equals mid!

🪜 The approach, step by step

  1. Set left = 0, right = len(nums) - 1.
  2. While left <= right:
  3. Compute mid = left + (right - left) // 2.
  4. If nums[mid] == target, return True.
  5. Handle ambiguous duplicates: If nums[left] == nums[mid] == nums[right]: left += 1; right -= 1; continue.
  6. If left half is sorted (nums[left] <= nums[mid]):
  7.   If nums[left] <= target < nums[mid]: right = mid - 1, else left = mid + 1.
  8. Else (right half is sorted):
  9.   If nums[mid] < target <= nums[right]: left = mid + 1, else right = mid - 1.
  10. Return False if loop terminates.

🎞️ Visual dry run — nums = [1, 0, 1, 1, 1], target = 0

        Shrink: left = 1, right = 3

Iter 2: left = 1, right = 3 → mid = 2, nums[mid] = 1 != target(0)
        nums[left]=0, nums[mid]=1 → left half sorted!
        0 <= target(0) < 1 → target in left half!
        right = mid - 1 = 1

Iter 3: left = 1, right = 1 → mid = 1, nums[mid] = 0 == 0! Match! Return True. ✓

✅ The solution

Reveal the commented solution (attempt it first!) 
def search(nums, target):
    left, right = 0, len(nums) - 1
    
    while left <= right:
        mid = left + (right - left) // 2
        
        if nums[mid] == target:
            return True
            
        # Ambiguous case: cannot determine sorted half
        if nums[left] == nums[mid] == nums[right]:
            left += 1
            right -= 1
            continue
            
        # Left half is sorted
        if nums[left] <= nums[mid]:
            if nums[left] <= target < nums[mid]:
                right = mid - 1
            else:
                left = mid + 1
        # Right half is sorted
        else:
            if nums[mid] < target <= nums[right]:
                left = mid + 1
            else:
                right = mid - 1
                
    return False

⏱️ Complexity

Average Time O(log n); Worst-case Time O(n) when nearly all elements are identical. Space O(1).

⚠️ Edge cases

  • All elements identical: e.g. [2, 2, 2, 2] searching for 3.
  • Target is the duplicate value itself.
