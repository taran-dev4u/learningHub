📋 The problem

Merge all overlapping intervals in a list and return the non-overlapping result.

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

Given an array of intervals where intervals[i] = [start_i, end_i], merge all overlapping intervals, and return an array of the non-overlapping intervals that cover all the intervals in the input.

Two intervals [a, b] and [c, d] overlap if and only if b ≥ c (assuming a ≤ c). To detect overlaps easily without quadratic comparisons, we sort all intervals by their start times.

🐢 Brute force vs optimal

Comparing every interval against all others to find overlaps takes O(N^2) or graph connected components. Sorting intervals by their start coordinates allows us to merge them in a single linear pass in O(N log N) time.

💡 Key insight: Sort by start. Once sorted, if the current interval starts after the last merged interval ends (curr[0] > res[-1][1]), they cannot possibly overlap—append curr as a new interval. Otherwise, they overlap—merge them by updating the end boundary: res[-1][1] = max(res[-1][1], curr[1]).

🪜 The approach, step by step

  1. Sort intervals in-place by start time: intervals.sort(key=lambda x: x[0]).
  2. Initialize merged = [intervals[0]].
  3. For each start, end in intervals[1:]:
    • Let last_start, last_end = merged[-1].
    • If start <= last_end: overlap detected! Update merged[-1][1] = max(last_end, end).
    • Else: no overlap. Append [start, end] to merged.
  4. Return merged.

🎞️ Visual dry run — intervals = [[1,3],[2,6],[8,10],[15,18]]:

1. Sorted: [[1,3], [2,6], [8,10], [15,18]]

✅ The solution

def merge(intervals: list[list[int]]) -> list[list[int]]:
    """
    Merges overlapping intervals by sorting by start time.
    """
    if not intervals:
        return []
        
    intervals.sort(key=lambda x: x[0])
    merged = [intervals[0]]
    
    for start, end in intervals[1:]:
        if start <= merged[-1][1]:
            merged[-1][1] = max(merged[-1][1], end)
        else:
            merged.append([start, end])
            
    return merged

⚡ Complexity analysis

  • Time Complexity: O(N log N) dominated by the sorting step. The linear scan takes O(N).
  • Space Complexity: O(N) to store the merged output intervals (or O(log N) for Python Timsort recursion stack).

🚨 Edge cases to watch out for

  • One interval completely inside another: e.g. [1, 10] and [2, 5]. The max(last_end, end) correctly keeps 10.
  • Adjacent touching intervals: e.g. [1, 4] and [4, 5]. Since 4 <= 4, they correctly merge into [1, 5].
