📋 The problem

Count sequences of numbers (order matters, reuse allowed) drawn from an array that sum to a target.

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

Given an array of distinct integers nums and a target integer target, return the number of possible combinations that add up to target. Note that different sequences (order matters, e.g., [1, 2] and [2, 1]) are counted as different permutations.

Because order matters, this is counting permutations! To reach target sum i, the last number chosen could be any num \in nums where num <= i: $$dp[i] = \sum_{num \in nums, num \le i} dp[i - num]$$ with base case $dp[0] = 1$ (one way to form sum 0: empty set).

🐢 Brute force vs optimal

Notice the loop order: - In Coin Change II (LC 518) (combinations, order does NOT matter), outer loop is coins, inner loop is amounts. - In Combination Sum IV (LC 377) (permutations, order DOES matter), outer loop is target amounts $1 \dots \text{target}$, inner loop is numbers!

💡 Key insight: Loop targets outer, coins inner: for i in range(1, target + 1): for x in nums: dp[i] += dp[i - x].

✅ The solution

Reveal the commented solution (attempt it first!) 
def combinationSum4(nums: list[int], target: int) -> int:
    dp = [0] * (target + 1)
    dp[0] = 1
    
    for i in range(1, target + 1):
        for num in nums:
            if i >= num:
                dp[i] += dp[i - num]
                
    return dp[target]

Complexity

Time: $O(\text{target} \times |nums|)$ — Nested iterations.
Space: $O(\text{target})$ — 1D DP table.
