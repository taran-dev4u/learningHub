📋 The problem

Return the k points closest to the origin.

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

Given points in 2D space, return the k closest points to (0, 0). Distance squared is x^2 + y^2 (no need for square root since distance is monotonic). We need the k smallest distances, so maintain a max-heap of size k: the point with the largest distance among the top k is at the root. If a new point has a smaller distance, it replaces the root.

🐢 Brute force first

Compute distance for all points, sort by distance, and take the first k points → O(n log n) time.

💡 Key insight: use a max-heap of size k storing (-dist, x, y). At any point, the heap holds the k closest points seen so far. If a new point is closer than the current worst in the heap, pop the worst and push the new one.

🪜 The approach, step by step

  1. Initialize a max-heap h = [].
  2. For each point (x, y): calculate distance d = x*x + y*y.
  3. Push (-d, x, y) to h.
  4. If len(h) > k, pop the root (which has the largest distance).
  5. Return [[x, y] for _, x, y in h].

🎞️ Visual dry run — points = [[1,3],[-2,2]], k = 1

[1, 3]  → dist = 1 + 9 = 10 → push (-10, 1, 3) → heap: [(-10, 1, 3)]
[-2, 2] → dist = 4 + 4 = 8  → push (-8, -2, 2) → heap size 2 > 1
        → pop (-10, 1, 3) (largest distance discarded)
        → heap: [(-8, -2, 2)]
Result: [[-2, 2]] ✓

✅ The solution

Reveal the commented solution (attempt it first!) 
import heapq

def kClosest(points, k):
    # Max-heap of size k: store negative distance so largest distance is popped first
    heap = []
    for x, y in points:
        dist = x * x + y * y
        heapq.heappush(heap, (-dist, x, y))
        if len(heap) > k:
            heapq.heappop(heap)
            
    return [[x, y] for _, x, y in heap]

⏱️ Complexity

Time O(n log k) — iterating through n points with heap of size at most k+1. Space O(k) — to store the k closest points.

⚠️ Edge cases

  • k == len(points): returns all points.
  • Ties in distance: any order is accepted.
  • Coordinates with negative values: squaring removes negative signs.

🐛 Common mistakes

  • Computing math.sqrt() for distance — floating point operations are slower and risk precision errors.
  • Using a min-heap of size n (O(n log n) space and time) instead of a max-heap of size k.
