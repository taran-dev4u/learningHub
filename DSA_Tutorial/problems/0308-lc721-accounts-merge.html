📋 The problem

Merge accounts that share any email; output each person's emails sorted under their name.

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

Given a list of accounts where each element accounts[i] is a list of strings: the first element is a name, and the remaining elements are emails. If two accounts share a common email, both accounts belong to the same person. Merge the accounts and return the list of merged accounts where emails are sorted lexicographically.

This is a connected components problem on a graph. The nodes of the graph are individual emails! If an account contains emails [e1, e2, e3], there are edges between e1 — e2 and e1 — e3. All emails in the same connected component belong to the same person.

🐢 Brute force vs optimal

Iteratively checking pairs of accounts for email intersections takes O(A2 × E), which is too slow. Using Disjoint Set Union (DSU) or DFS on an email adjacency graph merges all accounts in O(N × E log(N × E)), dominated only by the final sorting of emails.

💡 Key insight: Map each email to its owner's name. Within each account [name, e1, e2, ...], union the first email e1 with every other email e_i. After processing all accounts, group all emails by their DSU root representative: components[find(email)].append(email). Finally, format each component as [email_to_name[root]] + sorted(emails).

🪜 The approach, step by step

  1. Union-Find Data Structure: Initialize parent = {}. If an email is seen for the first time, set parent[email] = email.
  2. Record Name & Union Emails:
    • Maintain email_to_name = {}.
    • For each account name, *emails:
    • First email first_email = emails[0].
    • For every email in emails:
      • Record email_to_name[email] = name.
      • union(first_email, email).
  3. Group by Root:
    • Create groups = defaultdict(list).
    • For every email: groups[find(email)].append(email).
  4. Sort & Assemble:
    • For each group: result.append([email_to_name[root]] + sorted(emails)).
    • Return result.

✅ The solution

Python 3 — DSU by Email Strings 
from collections import defaultdict

def accountsMerge(accounts: list[list[str]]) -> list[list[str]]:
    """
    Merges accounts belonging to the same person using Disjoint Set Union on emails.
    """
    parent = {}
    email_to_name = {}
    
    def find(x):
        if parent[x] != x:
            parent[x] = find(parent[x])
        return parent[x]
        
    def union(x, y):
        rx, ry = find(x), find(y)
        if rx != ry:
            parent[rx] = ry

    # 1. Initialize parents and union emails within each account
    for account in accounts:
        name = account[0]
        first_email = account[1]
        
        for email in account[1:]:
            if email not in parent:
                parent[email] = email
            email_to_name[email] = name
            union(first_email, email)
            
    # 2. Group emails by their root representative
    groups = defaultdict(list)
    for email in parent:
        root = find(email)
        groups[root].append(email)
        
    # 3. Format result: [name] + sorted(emails)
    res = []
    for root, emails in groups.items():
        res.append([email_to_name[root]] + sorted(emails))
        
    return res

⚡ Complexity analysis

  • Time Complexity: O(N × K log(N × K)) where N is the number of accounts and K is the maximum number of emails per account. Union-Find operations take O(N × K × α(N × K)), and sorting the merged email lists takes O(total_emails log(total_emails)).
  • Space Complexity: O(N × K) to store parents, names, and groups.

🚨 Edge cases to watch out for

  • Same person name, different people: Two different people named "John" with completely different emails must NOT be merged. Since we only union by email connectivity, they naturally stay in separate components.
  • Duplicate emails inside a single account: Handled seamlessly by the hash map representation.
