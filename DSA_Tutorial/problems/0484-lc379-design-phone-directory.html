#379 Design Phone Directory MediumLeetCode

 

Pattern: Design Patterns › Subpattern 15.1: General / Specific Data Structure Design · Problem 484 of 699

📋 The problem

Design a phone directory that hands out unused numbers, checks availability, and recycles released numbers.

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

Design a Phone Directory which allocates and releases telephone numbers from $0$ to $ ext{maxNumbers} - 1$.

Requirements: - get(): Provide an unassigned number, or -1 if none available. - check(number): Return whether the number is currently available. - release(number): Free up an assigned number.

Queue + Hash Set (or Boolean Array): - available_queue: FIFO queue holding available numbers. - used_set: Hash set tracking numbers currently in use for $O(1)$ check and release deduplication.

🐢 Brute force vs optimal

Scanning an array for an available number takes $O(n)$. A queue of available numbers gives strict $O(1)$ for get, check, and release.

💡 Key insight: Maintain a FIFO queue of unused numbers and a set of used numbers. get pops from queue, release adds back to queue in $O(1)$!

✅ The solution

Reveal the commented solution (attempt it first!) 
from collections import deque

class PhoneDirectory:
    def __init__(self, maxNumbers: int):
        self.available = deque(range(maxNumbers))
        self.used = set()

    def get(self) -> int:
        if not self.available:
            return -1
        num = self.available.popleft()
        self.used.add(num)
        return num

    def check(self, number: int) -> bool:
        return number not in self.used

    def release(self, number: int) -> None:
        if number in self.used:
            self.used.remove(number)
            self.available.append(number)

Complexity

Time: $O(1)$ for get, check, and release.
Space: $O(N)$ where $N$ is maxNumbers.
