📋 The problem

Count pairs i<j with nums[i] > 2·nums[j].

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

Given an integer array nums, return the number of reverse pairs in the array. A reverse pair is a pair $(i, j)$ where $0 \le i < j < len(nums)$ and $nums[i] > 2 \times nums[j]$.

This is a variation of counting inversions! Use Merge Sort Divide-and-Conquer: When merging two sorted halves $nums[l \dots mid]$ and $nums[mid+1 \dots r]$: Both halves are already sorted! For each element $nums[i]$ in the left half, advance pointer $j$ in the right half while: $$nums[i] > 2 \times nums[j]$$ Because $nums[i]$ is increasing, pointer $j$ only moves forward (two pointers in $O(N)$)!

🐢 Brute force vs optimal

Nested loops take $O(N^2)$. Merge sort divide-and-conquer counts all reverse pairs in $O(N \log N)$ time.

💡 Key insight: Merge sort: count pairs before merging. Two pointers advance $j$ while $nums[i] > 2 \times nums[j]$, accumulating $(j - (mid + 1))$ in $O(N)$ time per level.

✅ The solution

def reversePairs(nums: list[int]) -> int:
    def merge_sort(l, r):
        if l >= r:
            return 0
        mid = (l + r) // 2
        count = merge_sort(l, mid) + merge_sort(mid + 1, r)
        
        # Count reverse pairs
        j = mid + 1
        for i in range(l, mid + 1):
            while j <= r and nums[i] > 2 * nums[j]:
                j += 1
            count += j - (mid + 1)
            
        # Merge sorted halves in place
        nums[l:r + 1] = sorted(nums[l:r + 1])
        return count
        
    return merge_sort(0, len(nums) - 1)

Complexity

Time: $O(N \log N)$ — Standard merge sort recurrence with $O(N)$ two-pointer scan.
Space: $O(N)$ — Temporary merge buffers and recursion stack.
