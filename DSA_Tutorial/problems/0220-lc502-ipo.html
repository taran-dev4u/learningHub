📋 The problem

Choose at most k projects, each needing capital and yielding profit, reinvesting profits, to maximize final capital.

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

You have initial capital w and can complete at most k distinct projects. Each project i has pure profit profits[i] and requires minimum capital capital[i]. Greedily, among all projects we can afford (capital <= w), we should always pick the one that gives the maximum profit.

🐢 Brute force first

In each of the k rounds, scan all projects to find affordable ones and pick the maximum profit → O(k * n).

💡 Key insight: sort projects by capital ascending. Maintain a max-heap of profits for all currently affordable projects. Each round, push all newly affordable projects into the heap, pop the maximum profit, and add it to capital w. Repeat k times.

🪜 The approach, step by step

  1. Sort projects by capital: projects = sorted(zip(capital, profits)).
  2. Initialize max-heap available_profits = [].
  3. Track index i = 0 in sorted projects.
  4. For _ in range(k):
  5. While i < n and projects[i][0] <= w: push -projects[i][1] to heap, advance i.
  6. If heap is empty (no affordable projects), break.
  7. w += -heappop(available_profits).
  8. Return w.

✅ The solution

import heapq

def findMaximizedCapital(k, w, profits, capital):
    n = len(profits)
    # Sort projects by required capital ascending
    projects = sorted(zip(capital, profits))
    
    available = []   # max-heap of profits for affordable projects
    i = 0
    
    for _ in range(k):
        # Add all newly affordable projects into the max-heap
        while i < n and projects[i][0] <= w:
            heapq.heappush(available, -projects[i][1])
            i += 1
            
        if not available:
            break    # cannot afford any more projects
            
        # Greedily choose the project with the highest profit
        w += -heapq.heappop(available)
        
    return w

⏱️ Complexity

Time O(n log n + k log n) — sorting takes O(n log n); each project is pushed and popped at most once in O(log n). Space O(n) for the projects list and heap.

⚠️ Edge cases

  • Capital never enough to start any project: returns initial w.
  • k >= n: all projects that can be afforded will be completed.
