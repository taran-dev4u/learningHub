📋 The problem

Design an LRU cache with get and put in O(1) average time; when capacity is exceeded, evict the least recently used key.

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

Where this fits

LRU Cache Design — Doubly linked list orders by recency; hashmap maps key → list node for O(1) access.

💡 Key idea
Dict → doubly-linked-list nodes: dict finds, list orders; move-to-front on every access, evict tail.

Why this pattern?

  • "O(1) average for every operation"
  • eviction by recency/frequency, capacity limits
  • time-versioned lookups (get value at timestamp)
  • two-way mappings, consistent grouping
