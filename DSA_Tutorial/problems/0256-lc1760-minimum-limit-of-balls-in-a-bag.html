#1760 Minimum Limit of Balls in a Bag MediumLeetCode

 

Pattern: Binary Search Patterns › Subpattern 8.3: On Answer / Condition Function · Problem 256 of 699

📋 The problem

Split balls in bags with limited operations to minimize the largest bag (binary search the answer).

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

You are given an integer array nums where nums[i] represents the number of balls in the i-th bag. You are also given an integer maxOperations. In one operation, you can take any bag and divide its balls into two new bags of positive sizes. Your penalty is the maximum number of balls in a bag. Return the minimum possible penalty after at most maxOperations.

🐢 Brute force first

Always split the largest bag using a max-heap: greedy split into two equal halves doesn't always yield the optimal penalty for future splits. Binary search on penalty is exact!

💡 Key insight: Can we achieve a maximum bag size of P (penalty)? For a bag of size x, to ensure no piece exceeds P, we must divide it into ceil(x / P) pieces, requiring ceil(x / P) - 1 = (x - 1) // P operations! If the sum of operations across all bags is <= maxOperations, penalty P is feasible.

🪜 The approach, step by step

  1. left = 1 (minimum possible penalty), right = max(nums).
  2. Helper canAchieve(P): calculate operations: sum((x - 1) // P for x in nums) <= maxOperations.
  3. While left < right:
  4. mid = left + (right - left) // 2.
  5. If canAchieve(mid): right = mid (try smaller penalty).
  6. Else: left = mid + 1.
  7. Return left.

🎞️ Visual dry run — nums = [9], maxOperations = 2

Range: [1, 9]
Iter 1: mid = 5 → (9 - 1) // 5 = 1 operation <= 2 → right = 5 (bag split into [5, 4])
Iter 2: left = 1, right = 5 → mid = 3 → (9 - 1) // 3 = 2 operations <= 2 → right = 3 (split into [3, 3, 3])
Iter 3: left = 1, right = 3 → mid = 2 → (9 - 1) // 2 = 4 operations > 2 → left = 3
left == right == 3. Penalty = 3! ✓

✅ The solution

Reveal the commented solution (attempt it first!) 
def minimumSize(nums, maxOperations):
    left, right = 1, max(nums)
    
    while left < right:
        mid = left + (right - left) // 2
        ops = sum((x - 1) // mid for x in nums)
        
        if ops <= maxOperations:
            right = mid
        else:
            left = mid + 1
            
    return left

⏱️ Complexity

Time O(n * log(max(nums))). Space O(1).

⚠️ Edge cases

  • maxOperations very large: penalty can reach 1.
  • All numbers already small.
