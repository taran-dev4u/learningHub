📋 The problem

Design a calendar that allows double bookings but rejects any event causing a triple booking.

Restated in our own words — the LeetCode icon above opens the formal statement with exact constraints and examples.

🧭 How to think about it

A triple booking happens when three events have some non-empty intersection. Implement a MyCalendarTwo class that allows events that do not cause a triple booking (double booking is allowed!).

Maintain two lists: 1. calendar: All booked single events. 2. overlaps: All double-booked interval intersections!

When booking $[start, end)$: 1. First, check if $[start, end)$ intersects with any interval in overlaps. If yes, it would cause a triple booking! Return False immediately! 2. If no conflict: Find all intersections between $[start, end)$ and existing intervals in calendar, and add those intersection intervals to overlaps! Add $[start, end)$ to calendar and return True.

🐢 Brute force vs optimal

Explicitly tracking the overlap intersections guarantees $O(N)$ check per booking.

💡 Key insight: Maintain overlaps list. Reject if new event touches any double-booking. Otherwise, compute new pairwise overlaps with calendar and accept.

✅ The solution

Reveal the commented solution (attempt it first!) 
class MyCalendarTwo:
    def __init__(self):
        self.calendar = []
        self.overlaps = []

    def book(self, start: int, end: int) -> bool:
        # Check against existing double-booked intervals
        for s, e in self.overlaps:
            if max(start, s) < min(end, e):
                return False # Would create triple booking!
                
        # Record new double-booked intervals
        for s, e in self.calendar:
            if max(start, s) < min(end, e):
                self.overlaps.append((max(start, s), min(end, e)))
                
        self.calendar.append((start, end))
        return True

Complexity

Time: $O(N)$ per booking call where $N$ is total booked events.
Space: $O(N)$ — Stores intervals and overlap segments.
