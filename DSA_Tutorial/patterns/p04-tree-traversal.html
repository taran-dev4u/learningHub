🧩 Tree Traversal Patterns (DFS & BFS)

6 subpatterns · 54 problems ·

1. Intuition — the mental model

Every tree problem is a traversal wearing a costume. The question is only: in what order do you visit nodes, and what do you carry — state passed down (path, bounds) or answers passed up (heights, sums)? DFS goes deep via recursion; BFS goes level-by-level via a queue.

💡 The “aha” insight
The recursive leap: solve the node, trust recursion for the subtrees. "Diameter" is not a path search — it is, at every node, left_height + right_height, maximized. Once you see each node asks one local question, hard problems become 5-liners.

2. Recognition signals

Think of this pattern when the problem says:

  • "level", "depth", "nearest", "zigzag by rows" → BFS
  • "path sum", "ancestor", "validate", "diameter" → DFS
  • BST + "k-th smallest / sorted order" → inorder
  • "serialize / reconstruct" → preorder

3. Master template

def dfs(node, state):                 # state flows DOWN (bounds, path...)
    if not node:
        return base                       # e.g. 0, True, None
    L = dfs(node.left,  new_state)
    R = dfs(node.right, new_state)
    return combine(node.val, L, R)        # answer flows UP

from collections import deque             # BFS by levels
q = deque([root])
while q:
    for _ in range(len(q)):               # freeze current level size
        node = q.popleft()
        if node.left:  q.append(node.left)
        if node.right: q.append(node.right)

A global self.best updated inside DFS handles "best anywhere in the tree" answers (diameter, max path sum) while the function still returns the "usable by parent" value — that split is the key trick.

4. Complexity of the template

O(n) time — each node visited once. Space: DFS O(h) recursion stack (h = height, log n balanced, n skewed); BFS O(w) queue (w = widest level, up to n/2).

5. Common mistakes

  • Validate BST with only child comparisons — pass down (lo, hi) bounds instead.
  • BFS levels without freezing len(q) — levels bleed together.
  • Confusing "return value for parent" with "global answer" in diameter-style problems.
  • Forgetting the None base case (crash) or returning the wrong neutral value.
