🧩 Two Pointer Patterns

7 subpatterns · 37 problems ·

1. Intuition — the mental model

Many problems ask about pairs or positions in an array. Brute force tries every pair — O(n²). Two pointers replaces "try everything" with two indices that move by a rule, and the rule guarantees you never need to look back. Each pointer moves at most n steps, so the whole thing is O(n).

💡 The “aha” insight
On a sorted array, comparing nums[left] + nums[right] to the target tells you which pointer is safe to move: sum too small → only moving left up can help; too big → only moving right down can. Every comparison permanently eliminates a whole row of pair-candidates.

2. Recognition signals

Think of this pattern when the problem says:

  • sorted array (or you may sort it) + find a pair/triplet
  • palindrome or symmetric comparison (compare ends)
  • do it in place with O(1) extra space (read/write pointers)
  • linked list: middle, cycle, k-th from end (fast & slow)
  • "remove/keep elements" while preserving relative order

3. Master template

# Converging (opposite ends)
left, right = 0, len(nums) - 1
while left < right:
    cur = nums[left] + nums[right]      # ← state you compare
    if cur == target:
        return [left, right]
    elif cur < target:
        left += 1                        # too small: need a bigger left
    else:
        right -= 1                       # too big: need a smaller right

# Read/write (in-place filtering)
write = 0
for read in range(len(nums)):
    if keep(nums[read]):                 # ← condition changes per problem
        nums[write] = nums[read]
        write += 1

Two shapes cover most problems: converging (ends → middle) and read/write (both start at 0, write lags). The third shape, fast & slow, lives on linked lists: fast moves two steps per slow step.

4. Complexity of the template

O(n) time — each pointer crosses the array once. O(1) space — just indices. If you must sort first, that dominates: O(n log n).

5. Common mistakes

  • Using converging pointers on an unsorted array — the elimination logic only holds when sorted.
  • Off-by-one: while left < right vs <= — decide whether pointers may meet.
  • Forgetting to skip duplicates in 3Sum-style problems (advance past equal values).
  • In fast/slow: writing while fast.next and fast — the null-check order crashes.
