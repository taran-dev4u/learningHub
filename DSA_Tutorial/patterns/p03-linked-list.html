🧩 Linked List Manipulation Patterns

5 subpatterns · 22 problems ·

1. Intuition — the mental model

Linked list problems are about rewiring pointers without losing pieces. There is no index access — only walking. Nearly every solution combines four moves: a dummy head (kills edge cases), fast & slow pointers (find middles/cycles), in-place reversal, and splice/merge.

💡 The “aha” insight
You rarely need extra memory: the list itself can be re-linked. "Reorder list" = find middle (fast/slow) + reverse second half + merge two lists — three primitives you already know, glued together.

2. Recognition signals

Think of this pattern when the problem says:

  • input is a linked list (that alone is the signal)
  • "reverse", "reorder", "swap in pairs", "rotate" nodes
  • "k-th from the end", "middle", "cycle" → fast & slow
  • "merge k sorted lists" → pairwise merge or heap of heads

3. Master template

dummy = ListNode(0, head)            # dummy head: prev of the real head
prev, cur = dummy, head

# In-place reversal core
p = None
while cur:
    cur.next, p, cur = p, cur, cur.next
# p is the new head

# Fast & slow
slow = fast = head
while fast and fast.next:
    slow, fast = slow.next, fast.next.next   # slow = middle when fast ends

The one-line triple assignment reverses safely because Python evaluates the right side first — the old cur.next is read before being overwritten.

4. Complexity of the template

O(n) time — constant passes. O(1) space is the standard expectation; recursion is allowed but costs O(n) stack.

5. Common mistakes

  • Overwriting cur.next before saving it — half the list floats away.
  • No dummy head → separate handling for "the answer is a new head", often buggy.
  • Cycle problems: comparing .val instead of node identity (is).
  • After splitting a list, forgetting to set the split point's .next = None.
