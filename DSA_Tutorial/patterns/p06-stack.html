🧩 Stack Patterns

6 subpatterns · 32 problems ·

1. Intuition — the mental model

A stack remembers unfinished business in exactly the order you must return to it. Open brackets wait for closers; operators wait for operands; in monotonic stacks, elements wait for their "next greater". Push when a decision can't be made yet, pop when today's element resolves it.

💡 The “aha” insight
The monotonic stack: keep the stack decreasing; when a bigger element arrives, it IS the "next greater element" for everything it pops. Each index pushes once, pops once — every "for each element find the next bigger/smaller" question drops from O(n²) to O(n).

2. Recognition signals

Think of this pattern when the problem says:

  • brackets/tags to match or validate
  • "next greater / next warmer / previous smaller" element
  • histogram areas, trapped water, "can see over"
  • evaluate/parse an expression, decode nested strings
  • undo semantics or "remove adjacent pairs"

3. Master template

# Monotonic (decreasing) stack — next greater element
stack = []                              # holds INDICES of unresolved elements
res = [-1] * len(nums)
for i, x in enumerate(nums):
    while stack and nums[stack[-1]] < x:   # x resolves the waiting ones
        j = stack.pop()
        res[j] = x                          # x is j's next greater
    stack.append(i)

# Matching
for ch in s:
    if ch in pairs:  stack.append(ch)
    elif not stack or pairs[stack.pop()] != ch:
        return False
return not stack

Store indices, not values — most problems (daily temperatures, spans, histogram) need distances or widths, which only indices give you.

4. Complexity of the template

O(n) time — each element is pushed and popped at most once (the while loop is amortized). O(n) space worst case (fully decreasing input).

5. Common mistakes

  • Returning True on matching problems without checking the stack is EMPTY at the end.
  • Choosing the wrong monotonic direction — decreasing stack finds next greater; increasing finds next smaller. Dry-run 3 elements to check.
  • Strict vs non-strict comparison (< vs <=) — decides how duplicates resolve.
  • Histogram: forgetting the final flush (append a 0 bar or drain the stack after the loop).
