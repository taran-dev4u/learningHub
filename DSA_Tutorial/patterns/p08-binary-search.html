🧩 Binary Search Patterns

5 subpatterns · 29 problems ·

1. Intuition — the mental model

Binary search needs only one property: a test that splits the space into "all False, then all True" (monotonic). Compare at the middle, discard the losing half, repeat — O(log n). The deep version: the array is optional. You can binary-search the answer itself ("can we do it with capacity c?") as long as feasibility is monotone.

💡 The “aha” insight
Reframe optimization as decision: "minimum ship capacity" is hard, but "can capacity c ship everything in d days?" is an easy O(n) check — and if c works, every bigger c works. Binary search over c: O(n log range).

2. Recognition signals

Think of this pattern when the problem says:

  • sorted (or rotated-sorted) array + find/insert position
  • "minimize the maximum" / "maximize the minimum"
  • a feasibility check that flips once as a parameter grows
  • O(log n) demanded explicitly
  • find a peak / a boundary between regions

3. Master template

# Lower-bound shape: smallest index where check(i) is True
lo, hi = 0, n            # hi = n allows "no answer" result
while lo < hi:
    mid = (lo + hi) // 2
    if check(mid):        # True region is on the right side's left edge
        hi = mid          # mid might be the answer — keep it in range
    else:
        lo = mid + 1      # mid is definitely not — discard it
return lo                 # first True (or n if none)

# Binary search on the ANSWER
lo, hi = min_possible, max_possible
while lo < hi:
    mid = (lo + hi) // 2
    if feasible(mid): hi = mid
    else:             lo = mid + 1

Learn ONE shape well. This half-open [lo, hi) lower-bound shape terminates cleanly (range shrinks every turn), never skips the answer, and expresses find-exact, insert-position, first/last occurrence, and answer-space searches with only check changing.

4. Complexity of the template

O(log n) comparisons; answer-space version O(n log range) — n per feasibility check, log range checks.

5. Common mistakes

  • Infinite loop from hi = mid with a closed-interval template — mixing conventions. Pick one, always.
  • Rotated arrays: forgetting exactly one half is always sorted — test which, then decide.
  • Using mid = (lo+hi)//2 then eliminating mid from the wrong side.
  • Answer-space search with a non-monotone check — verify feasibility really flips once.
