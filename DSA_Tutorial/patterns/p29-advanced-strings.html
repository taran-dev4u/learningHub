🧩 Advanced String Algorithm Patterns

3 subpatterns · 7 problems ·

1. Intuition — the mental model

Naive substring search re-compares up to O(n·m) characters because it forgets everything after each mismatch. The advanced algorithms all monetize memory of what already matched: KMP precomputes how much of a match survives a mismatch; Rabin-Karp compares rolling hashes in O(1); Manacher reuses palindrome symmetry. Total: O(n+m) where naive pays O(n·m).

💡 The “aha” insight
KMP's failure table answers one question: "after matching pattern[0..k] and failing, what is the LONGEST proper prefix of the pattern that is also a suffix of what matched?" Jump there instead of restarting — the text pointer never moves backwards, guaranteeing linear time.

2. Recognition signals

Think of this pattern when the problem says:

  • find/count occurrences of a pattern in a long text
  • "shortest palindrome by prepending", "longest prefix = suffix" → failure function
  • many substring-equality checks → rolling hash
  • "repeated substring pattern" / string periodicity
  • longest palindromic substring in O(n) explicitly → Manacher

3. Master template

# KMP failure table: fail[i] = length of longest proper prefix of
# pat[0..i] that is also its suffix
def build_fail(pat):
    fail = [0] * len(pat)
    k = 0
    for i in range(1, len(pat)):
        while k and pat[i] != pat[k]:
            k = fail[k - 1]            # fall back to shorter border
        if pat[i] == pat[k]:
            k += 1
        fail[i] = k
    return fail

def kmp_search(text, pat):             # O(n + m)
    fail, k = build_fail(pat), 0
    for i, ch in enumerate(text):
        while k and ch != pat[k]:
            k = fail[k - 1]
        if ch == pat[k]:
            k += 1
        if k == len(pat):
            yield i - k + 1            # match start
            k = fail[k - 1]</code>

Rabin-Karp rolling hash: h = (h·B + new − old·Bᵐ) mod P — O(1) per slide; verify hash hits by direct compare (collisions). Periodicity: s repeats iff len(s) % (len(s) − fail[-1]) == 0 with fail[-1] > 0.

4. Complexity of the template

KMP O(n+m) time, O(m) space; Rabin-Karp O(n+m) average; Manacher O(n). Against naive O(n·m) — state the gap, it's the motivation.

5. Common mistakes

  • Failure table "proper prefix" — the whole string never counts as its own border.
  • Rabin-Karp trusting hash equality without verifying — collisions exist.
  • Rolling hash without modular care — huge numbers or biased collisions.
  • Reaching for KMP when text.find(pat) or a window suffices — know when it's overkill (then say why you know KMP anyway).
