Module 0.2 — Arrays, Dynamic Arrays, Strings & Matrices

The array is the most fundamental data structure: a row of boxes in memory. Almost everything else (stacks, heaps, hash tables, strings) is built on top of it.

1. What an array is

Analogy. An array is a row of numbered mailboxes in an apartment lobby. The boxes are physically side by side, all the same size, and numbered 0, 1, 2, … Knowing the row's starting position and a box number, you can walk directly to any box without opening the others.

The problem it solves. Programs need to store many values of the same kind and grab any one of them instantly. Without arrays you'd store values in separate variables (a1, a2, a3…) — impossible to loop over, impossible to size at runtime.

Plain-English definition. An array is a contiguous block of memory holding elements of the same size, where each element is reachable instantly by its index (position number, starting at 0).

Memory layout — why access is O(1)

Memory address:   1000   1004   1008   1012   1016
                ┌──────┬──────┬──────┬──────┬──────┐
arr =           │  17  │  42  │   8  │  99  │  23  │   (4 bytes each)
                └──────┴──────┴──────┴──────┴──────┘
index:              0      1      2      3      4

address_of(arr[i]) = 1000 + i × 4      ← one multiplication + one addition
so arr[3] = memory at 1000 + 3×4 = 1012 → instant, no searching

Why O(1): finding an element is pure arithmetic — the cost doesn't depend on how many elements exist. This formula is the whole secret of arrays.

Python noteA Python list is a dynamic array of references: the contiguous block stores pointers to objects, not the objects themselves. The O(1)-indexing logic is identical.

2. Every operation, from scratch

2.1 Create / initialize

empty   = []                    # empty dynamic array
zeros   = [0] * 5               # [0, 0, 0, 0, 0]
squares = [i * i for i in range(5)]   # [0, 1, 4, 9, 16]
copy_of = list(other)           # shallow copy, O(n)

Complexity: creating with n elements is O(n) time and space — each slot must be written once.

Pitfall[[0]*3]*4 creates 4 references to the same inner list — change one row and all rows change. Use [[0]*3 for _ in range(4)].

2.2 Access / peek — O(1)

arr = [17, 42, 8, 99, 23]
arr[0]      # 17  (first)
arr[-1]     # 23  (Python: negative index counts from the end)
arr[2] = 5  # update is also O(1): jump to the slot, overwrite

Edge cases: arr[5] on a 5-element list raises IndexError; an empty array has no valid index at all — always check if arr: first.

2.3 Search — O(n) unsorted, O(log n) sorted

Analogy: finding a friend's apartment when you don't know the number — you must knock door to door.

def linear_search(arr, target):
    for i, x in enumerate(arr):   # visit every slot until found
        if x == target:
            return i
    return -1                     # convention for "not found"

Dry run on [17, 42, 8], target 8: check 17 (no) → 42 (no) → 8 (yes) → return 2. Worst case checks all n → O(n). If the array is sorted, binary search cuts this to O(log n) — that's Pattern 8.

2.4 Insert

Analogy: squeezing into the middle of a packed movie-theater row — everyone to your right must shift one seat over.

insert 50 at index 1:

  before:  [17][42][ 8][99]
  shift →       [42][ 8][99] each move right one slot (from the END backward)
  after:   [17][50][42][ 8][99]
            0   1   2   3   4   ← 3 elements moved
arr.append(x)        # at END:    O(1) amortized (see resizing below)
arr.insert(1, 50)    # at index:  O(n) — shifts everything after index right
arr.insert(0, x)     # at FRONT:  O(n) — shifts ALL n elements (worst spot)

Complexity: end O(1) amortized; front/middle O(n) because of shifting. Why: contiguity is non-negotiable — there can be no gaps, so room must be made.

2.5 Delete

delete index 1:

  before:  [17][50][42][ 8][99]
  remove:  [17][  ][42][ 8][99]
  shift ←        [42][ 8][99] each move left one slot
  after:   [17][42][ 8][99]
arr.pop()        # from END:   O(1) — nothing shifts
arr.pop(1)       # by index:   O(n) — shifts the tail left
arr.remove(42)   # by VALUE:   O(n) — search O(n) + shift O(n)
Swap-and-pop trickIf order doesn't matter, delete index i in O(1): arr[i] = arr[-1]; arr.pop(). Overwrite the victim with the last element, then chop the end. Used in P18's O(1) Insert/Delete/GetRandom.

2.6 Update / modify — O(1)

arr[2] = 99            # direct overwrite, O(1)
arr[0], arr[3] = arr[3], arr[0]   # swap — the workhorse of in-place algorithms

2.7 Traverse — O(n)

for x in arr:                  # values
for i in range(len(arr)):      # indices
for i, x in enumerate(arr):    # both
for x in reversed(arr):        # right to left, no copy
# pairs of neighbors:
for i in range(len(arr) - 1):
    left, right = arr[i], arr[i + 1]

Edge cases: never add/remove elements of a list while iterating over it — you'll skip items. Iterate over a copy or build a new list.

3. Dynamic arrays — how a list grows

Analogy. A photo album with fixed pages. When it's full, you buy an album twice as big and move every photo into it. Moving day is painful, but it buys a long stretch of effortless additions.

The problem it solves. Plain arrays have fixed size (the memory beyond the block belongs to other data). But programs rarely know sizes in advance. A dynamic array fakes resizability: it keeps a bigger hidden block (capacity) than the visible length, and when capacity runs out, it reallocates.

append into spare capacity — O(1):
  len 3, cap 4:   [a][b][c][ · ]   →  append(d) → [a][b][c][d]

append when FULL — O(n) this one time:
  len 4, cap 4:   [a][b][c][d]
    1. allocate new block, cap 8:  [ · ][ · ][ · ][ · ][ · ][ · ][ · ][ · ]
    2. copy all 4 over:            [a][b][c][d][ · ][ · ][ · ][ · ]
    3. write the new element:      [a][b][c][d][e][ · ][ · ][ · ]

Because capacity doubles, expensive copies happen at sizes 1, 2, 4, 8, 16… The total copy work for n appends is 1+2+4+…+n ≤ 2n, so each append costs O(1) amortized (Module 0.1 §5 proves this).

Build a dynamic array from scratch (to see the machinery) 
class DynamicArray:
    def __init__(self):
        self.capacity = 1          # size of the hidden block
        self.length = 0            # how many slots are actually used
        self.data = [None] * 1     # simulate a raw fixed block

    def get(self, i):
        if not 0 <= i < self.length:
            raise IndexError("index out of range")
        return self.data[i]                       # O(1): direct slot

    def set(self, i, value):
        if not 0 <= i < self.length:
            raise IndexError("index out of range")
        self.data[i] = value                      # O(1): overwrite

    def append(self, value):
        if self.length == self.capacity:          # full → resize first
            self._resize(2 * self.capacity)       # doubling keeps appends O(1) amortized
        self.data[self.length] = value
        self.length += 1

    def pop(self):
        if self.length == 0:
            raise IndexError("pop from empty array")
        value = self.data[self.length - 1]
        self.data[self.length - 1] = None         # release the reference
        self.length -= 1
        return value                              # O(1): no shifting at the end

    def insert(self, i, value):
        if self.length == self.capacity:
            self._resize(2 * self.capacity)
        for j in range(self.length, i, -1):       # shift right, END first so
            self.data[j] = self.data[j - 1]       # nothing is overwritten
        self.data[i] = value
        self.length += 1                          # O(n) because of the shift

    def delete(self, i):
        for j in range(i, self.length - 1):       # shift left over the gap
            self.data[j] = self.data[j + 1]
        self.data[self.length - 1] = None
        self.length -= 1                          # O(n)

    def _resize(self, new_capacity):
        new_data = [None] * new_capacity
        for i in range(self.length):              # copy every element: O(n),
            new_data[i] = self.data[i]            # but happens rarely
        self.data = new_data
        self.capacity = new_capacity
OperationComplexityWhy
access / update by indexO(1)address arithmetic
append / pop at endO(1) amortizedspare capacity; rare doubling copy
insert / delete at front or middleO(n)shifting to preserve contiguity
search unsortedO(n)must potentially look everywhere
search sortedO(log n)binary search halves the range

4. Strings

Plain English: a string is an array of characters — same contiguous layout, same O(1) indexing, same O(n) search. One huge difference in Python: strings are immutable. You can read s[2] but never write s[2] = 'x'.

Why immutability exists: immutable strings can be safely shared, cached, and used as hash-map keys (their hash can never change behind your back — see Module 0.3).

The string-building trap

# BAD — O(n²): every += copies the ENTIRE string built so far
s = ""
for ch in pieces:
    s += ch          # copy of len(s) chars, every iteration

# GOOD — O(n): collect in a list, join once at the end
parts = []
for ch in pieces:
    parts.append(ch) # O(1) amortized
s = "".join(parts)   # single O(n) pass

Why the bad one is O(n²): copies of size 1+2+3+…+n = n(n+1)/2. The fix — build a list, join once — appears in nearly every string problem.

Slicing

s = "algorithm"
s[0:4]    # "algo"   — slice [start, end)  (end excluded)
s[4:]     # "rithm"
s[:4]     # "algo"
s[::-1]   # "mhtirogla" — reversed copy
s[::2]    # "agrtm"  — every 2nd char

Cost warning: every slice copies — s[1:] is O(n) time and space, not O(1). A recursion that slices each level silently becomes O(n²). Pass indices instead of slices.

Common string toolbox

s.split(",")       # string → list, O(n)
",".join(parts)    # list → string, O(n)
s.lower(), s.upper(), s.strip()     # new strings (immutability!), O(n)
ord('a')           # 97  — char → code; ord(c) - ord('a') gives 0..25
chr(98)            # 'b' — code → char
s.startswith("al"), s.find("go")    # find returns index or -1, O(n·m) naive

5. 2D arrays (matrices)

Analogy. A spreadsheet: rows and columns. In memory it's a list whose elements are row-lists.

grid = [[1, 2, 3],
        [4, 5, 6]]        2 rows × 3 cols

grid[r][c]:  row first, then column
grid[1][2] = 6            r = 1 (second row), c = 2 (third column)

rows = len(grid)          # 2
cols = len(grid[0])       # 3  (guard: grid must be non-empty!)

Create, traverse, neighbors

rows, cols = 3, 4
grid = [[0] * cols for _ in range(rows)]   # NEVER [[0]*cols]*rows (shared rows!)

# row-major traversal (the natural order)
for r in range(rows):
    for c in range(cols):
        visit(grid[r][c])          # O(rows × cols) — every cell once

# 4-directional neighbors with bounds checking — the grid-problem idiom
for dr, dc in ((1,0), (-1,0), (0,1), (0,-1)):
    nr, nc = r + dr, c + dc
    if 0 <= nr < rows and 0 <= nc < cols:   # check BEFORE touching grid[nr][nc]
        visit(grid[nr][nc])

Transpose & row reversal (building blocks of rotation)

transpose: flip across the main diagonal (rows become columns)

  1 2 3      1 4 7
  4 5 6  →   2 5 8        element (r,c) moves to (c,r)
  7 8 9      3 6 9

rotate 90° clockwise = transpose THEN reverse each row:
  1 4 7      7 4 1
  2 5 8  →   8 5 2
  3 6 9      9 6 3
def transpose_in_place(m):              # square matrix only
    n = len(m)
    for r in range(n):
        for c in range(r + 1, n):       # only above the diagonal,
            m[r][c], m[c][r] = m[c][r], m[r][c]   # else you'd swap back!

def rotate_90_clockwise(m):
    transpose_in_place(m)
    for row in m:
        row.reverse()                   # O(n²) total, O(1) extra space

Dry run of transpose on the 3×3 above: swaps (0,1)↔(1,0): 2↔4, (0,2)↔(2,0): 3↔7, (1,2)↔(2,1): 6↔8. Diagonal 1,5,9 never moves. This exact pair of tricks is P2.1 In-place Rotation.

7. Edge cases & classic mistakes

  • Empty input. arr[0] crashes; len(grid[0]) crashes on an empty grid. Always handle [] first.
  • Single element. Loops like range(len(arr)-1) simply don't run — make sure that's the right answer.
  • Off-by-one. range(n) ends at n−1; slices exclude the end; the last index is len(arr)-1. When unsure, dry-run with a 2-element array.
  • Aliasing. b = a copies the reference, not the list — mutating b mutates a. Copy with a[:] or list(a); nested lists need copy.deepcopy.
  • Mutating while iterating. Removing items inside for x in arr skips elements.
  • Insert/delete at front in a loop. n× insert(0, x) is O(n²). Use collections.deque (Module 0.5) for O(1) at both ends.
  • String += in a loop — O(n²). Use the list + join idiom.
  • Shared rows from [[0]*c]*r — every row is the same object.

8. When to use / recognition signals

Reach for an array when…you need ordered storage with instant access by position, lots of end-appends, or in-place rearrangement (sorting, swapping, partitioning). Cache-friendliness makes arrays the fastest structure in practice when they fit the access pattern.
Avoid (or augment) when…you do frequent insertions/deletions at the front or middle (→ linked list / deque), need fast membership tests by value (→ hash set), or need fast min/max retrieval as data changes (→ heap).

9. Check yourself

Q1. Why is arr[i] O(1) but searching for a value O(n)?

Indexing is address arithmetic: start + i × size. Searching by value has no formula — the value could be in any slot, so each must be examined until found.

Q2. nums.insert(0, x) done n times — total complexity?

O(n²). Each front-insert shifts all current elements: 0+1+2+…+(n−1) ≈ n²/2 shifts.

Q3. Why does s += ch in a loop cost O(n²) while parts.append(ch) + join costs O(n)?

Strings are immutable, so each += allocates a brand-new string and copies everything built so far (1+2+…+n copies). The list collects references with O(1) amortized appends, and join makes exactly one final O(n) pass.

Q4. What's wrong with grid = [[0]*3]*4?

The outer *4 repeats the same row object 4 times. grid[0][0]=9 sets column 0 of every row. Use a comprehension: [[0]*3 for _ in range(4)].

Q5. Rotating a square matrix 90° clockwise in place — which two steps?

Transpose (swap across the main diagonal, touching only pairs above the diagonal), then reverse each row. Both are O(n²) time, O(1) extra space.
