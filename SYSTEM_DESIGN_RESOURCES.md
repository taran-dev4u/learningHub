## 6. 🧭 Interview Frameworks & Approaches

### The RESHADED Framework (8-Step Methodology)

> The most structured approach to system design interviews:

| Step | Name | Description |
|:-----|:-----|:------------|
| **R** | Requirements | Clarify functional & non-functional requirements, DAUs, read/write ratios |
| **E** | Estimation | Back-of-the-envelope calculations (traffic, storage, bandwidth) |
| **S** | Storage Schema | Data model, SQL vs NoSQL decisions |
| **H** | High-level Design | Bird's-eye view: Clients → Load Balancers → API Servers → Databases |
| **A** | API Design | Define RESTful endpoints, request/response formats |
| **D** | Detailed Design | Address bottlenecks, implement sharding, caching, message queues, CDNs |
| **E** | Evaluation | Review against requirements, discuss trade-offs (Consistency vs Availability) |
| **D** | Distinctive Component | Advanced challenge that demonstrates seniority |

**Sources:** [System Design Handbook](https://systemdesignhandbook.com/), ByteByteGo

### Company-Specific Interview Styles

| Company | Style & Focus |
|:--------|:-------------|
| **Google** | Scalability, data processing pipelines, deep dives into specific components. Tests reasoning about complex distributed systems. |
| **Meta** | Product-oriented. "Pirate" rubric (clarification, estimation, tradeoffs). Expects product features and user growth considerations. |
| **Amazon** | Operational excellence + Leadership Principles. Expects discussion of failure handling, maintenance, real-world constraints. |
| **Netflix** | Conversational, domain-specific. No whiteboard. Open-ended discussions about the team's domain. Tests for fault tolerance and CDN expertise. |
| **Microsoft** | Broad architectural knowledge, scalability, bridging high-level design with concrete implementation. |
